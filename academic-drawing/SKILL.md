# 科技绘图

用于从文字、数据、草图或现有图片创建、修改和检查科研静态图。开始前读取当前项目适用的术语、绘图和版式规范。用户明确要求优先；项目已有约定在该项目内适用，不把某个项目的 TikZ 习惯扩展成通用默认。

## 默认工具选择

**解释结构与机制用图像大模型，简单框图用 TikZ，定量关系用 Matplotlib。** 这里的“大模型生成”指调用图像生成能力直接产出图片，不是让语言模型编写复杂 TikZ。

| 图片任务 | 默认工具 | 按需读取 |
|---|---|---|
| 系统架构、方法总览、模块关系、数据流 | 图像模型 | [架构图](references/architecture-diagrams.md)、[框架图设计](references/framework-diagrams.md) |
| 算法流程、处理管线、决策、状态转换 | 图像模型 | [流程图](references/flowcharts.md) |
| 神经网络、张量流、训练与推理机制 | 图像模型 | [神经网络图](references/neural-network-diagrams.md) |
| 研究设计、纳入排除、文献筛选流程 | 图像模型，精确计数可独立排版 | [研究流程图](references/study-flow-diagrams.md) |
| 生物通路、分子关系、区室与机制 | 图像模型 | [生物通路](references/biological-pathways.md) |
| 器官、细胞、装置、材料、概念场景 | 图像模型 | [科研插画](references/scientific-illustrations.md) |
| 少量节点、单层分组、短标签和简单连接的框图 | TikZ | 对应图型参考、[TikZ 模板](templates/tikz_template.tex) |
| 函数曲线、柱状图、折线、散点、分布、热图、实验与统计结果 | Matplotlib | [数据图](references/data-plots.md) |
| 机制图与结果图组成的多面板图 | 按面板分别选择 | [多面板图](references/multipanel-figures.md) |

“能用框和箭头表达”“拓扑必须准确”“有公式或可编辑文字”都不足以把复杂图路由到 TikZ。多级嵌套、密集交互、张量展开、复杂循环和多面板机制图仍默认用图像模型；难以准确生成的文字可放入独立的可编辑排版层。已有图的局部修改保留其实现，用户明确指定工具时遵从要求。

必须从数值读取位置、长度、面积、颜色或误差的图用 Matplotlib，不能让图像模型重画数据。数组、矩阵若只解释索引或元素映射，按机制示意处理；若要比较数值分布，则按数据图处理。纯数学曲线也属于 Matplotlib 路径。

绘制前从已有要求确定最终物理尺寸、标签方式和交付格式，并验证所选工具是否能实际提供。字体外观、字号可读性、文字可编辑、全部图元可编辑和纯矢量是不同要求；仅要求 PDF 或清晰文字不等于要求纯矢量。信息已足够时直接执行，不把这些项目变成固定问卷。

用户明确要求完整真实矢量或所有图元可编辑时，可将已核验设计完整重建为 SVG、TikZ 等适合项目的矢量对象，文字与图元在同一次布局中排版；重查语义并记录实际实现。该要求优先于默认路由及此前仅限模型原生文字的选择，不再反复提示模型“生成矢量 PNG”，也不只覆盖文字后宣称全图矢量。普通模型图仍保留原生栅格；用户明确要求同时保留相互不兼容的条件时，说明工具边界，只澄清该冲突。

## 共同原则

- **让核心答案在图上可见。** 明确读者已知什么、卡在哪里，以及答案对应的对象、状态变化或对照关系。两种机制不能只换标题和颜色却画成相同流程；图注补定义与条件，不代替图上缺失的关键区别。
- **事实与画法分开。** 先核实对象、关系、方向、条件和数量，再决定表示与布局。不从参考图或领域常识补出未提供的模块、连接、实验结果或样本数。
- **科学准确性是所有路径的义务。** 模型生成图也要逐字核对标签、逐条核对连线；科学错误不能由审美评分抵消。不得生成或修改冒充真实实验、显微、医学或观测证据的图片。
- **风格服务于解释。** 颜色表达语义，并配合文字、形状、位置或线型。先修层级与关系，再调配色。默认青绿主色、白底、浅填充、清晰细轮廓和圆角正交连接；已有项目或参考风格优先。
- **从初稿按最终尺寸设计。** 使用真实标签和目标宽度，检查文字、图标与框体的比例和内边距；交付前查看实际成图，已有排版文件时再检查嵌入后的完整页面。不能以放大预览清楚替代成书可读。
- **如实交付。** Matplotlib/TikZ 保存源文件及真实矢量输出；模型图保存原生栅格、提示词和生成记录。将 PNG 装进 PDF/SVG、修改 DPI 元数据或上采样都不产生真实矢量或新增细节。

## 图内标注与图注分工

图内文字以必要标注为限，不以独立讲解完整过程为目标。绘制前从完整事实中筛出最小标注清单：仅保留识别元素或消除歧义所必需的对象名、变量、算子、坐标与单位，以及无法由结构辨认的端口、分支条件或数量。不是每个元素、每条边都要加字；方向能由箭头看出、归属能由位置看出时，不再写“流向”“输入到”“属于”等说明。完整事实清单用于核验，不全部显示在图上。

逐项尝试删去文字：若仍能认出元素并追踪关系，图内就不保留；有解释价值的过程、条件和示例设定放入图注或正文，重复与无关说明直接删除，不机械搬到图注。若删去会混淆运算、来源、时序、尺度或分支，则保留最短准确标识。图内不放全图标题、逐步叙述或结论口号；同一对象只在需要识别的位置标一次，不同时给分区、框体和内部图标重复命名。

例如拼接节点已有 `C` 或 `Concat` 时，“旧通道与新通道拼接”放到图注，也不再额外贴“通道”等说明性短词；拼接轴不是当前比较或解释重点时在图注定义，相加仍以 `+` 区分。必要性取决于信息作用，不取决于文字长短。变量、索引、维度或公式若正是当前图要解释的对象则保留，不能把精简理解成删除数学内容。图面负责呈现元素及其关系，图注解释读法与条件，详细推导留在正文。

布局先按项目正文或单栏宽度试排；依次精简标注与冗余图元、调整组件比例和对齐、收紧组内空白、重排端口并降低绕线，再判断是否需要跨栏，不通过整体缩图或缩小字号换取紧凑。主计算区域获得足够面积，辅助回路不喧宾夺主；横向管线的输出放在阅读末端，同级或对照结果对齐。移动、缩放框体时联动内部内容、端口和连接；圆节点按真实标签留足内边距。

同轴相邻元素直连；模块连接优先横平竖直、少折点并保持统一圆角。先固定真实起止端口与关系，再消除交叉、压低外绕高度、减少折点和冗余长度；汇合线准确落在目标算子或端口，分叉与转弯分开。几何映射、轨迹和张量透视等有语义的斜线或曲线保留，不为整齐改变拓扑。详细规则见下面的布局参考。

布局与样式任务读取 [构图与布局](references/composition-layout.md) 和 [视觉样式](references/visual-style.md)。复杂解释图再读 [概念设计](references/concept-design.md)；表达未定时按理解难点查看 [对照图例](references/design-examples.md)。提供参考图或统一系列图片时读取 [参考风格迁移](references/reference-style-transfer.md)，用适量代表样张校准后再批量制作，不增加固定审批阶段。交付前读取 [质量检查](references/quality-checklist.md)。只修字体、颜色或已确定的局部关系时，不重新启动候选设计。

## 设计意图与精修

新图或整体改版时读取 [设计意图与精修](references/design-intent-and-refinement.md)。在事实清单之后，用简短、可执行的视觉说明确定焦点、空间分工、重复元素的节奏、颜色职责和文字层级，再进入绘制；系列图沿用已有说明，局部修订只更新受影响规则。说明并入已有规划或生成记录，不要求另写艺术宣言、命名风格或等待批准。

借鉴 `canvas-design` 的空间表达和细节精修，但科研关系、变量与结论必须清楚可定位，不能隐晦表达。完成科学与阅读核验后，再检查整体构图和局部工艺：优先删去冗余、收敛间距与层级、修正端点和基线，不用增加图案、纹理或装饰来制造完成感。科学缺口仍应补全，数据位置与比例不因视觉平衡而改变。已有结果满足检查时直接交付，不为固定轮次重新生成。

## 图像模型路径

绘制架构、流程、模型、通路和插画时读取 [模型绘图流程](references/image-model-workflow.md)，按“事实清单 → 视觉规划 → 风格细化 → 生成 → 视觉评审 → 缺陷修订”执行。流程借鉴 PaperBanana 的职责分工，不要求固定数量的代理、参考图或重生成轮次。

优先使用当前环境内置的图像生成与编辑工具，本环境为 `image_gen`。遵循工具实际声明的参数、参考图片机制及输出方式；不编造模型名、尺寸、质量、种子或输出路径参数。不因为普通生成失败自动切换到需要密钥或额外付费的 API；工具不可用时说明限制，并完成不依赖生成的设计材料。

默认生成包含模块、必要短标签、箭头和语义分组的完整图；图例仅在无法直接辨认编码时使用，不强制先做无文字底图。提示词分别给出最小标注清单与完整边清单，明确不增加清单外的标题、过程句或重复标注；生成后回到源材料校对。复杂公式、长中文、精确计数或反复生成错误的标签，可预留位置并用 SVG、LaTeX 或其他可编辑排版层添加，局部修正后重新检查。不能因标注难生成而把复杂图整体改回 TikZ。

用户明确要求模型原生文字时，保留该路径并通过模型编辑修订，不擅自留白、覆盖文字或添加标注层。标签默认常规字重；加粗线条不意味着加粗文字，字体外观近似不等于准确嵌入指定字体。

图片用于项目时，将选定产物与记录保存到项目资源目录，不能让正文只引用工具缓存。模型/参数未暴露时记录“工具未暴露”，不猜测。保留提示词可重新生成，不承诺复原相同像素。

## Matplotlib 路径

用显式 Figure/Axes 绘制，保存数据来源、变量映射、处理规则和可运行代码。可从 [Matplotlib 模板](templates/matplotlib_template.py) 复制并按主题重命名，也可为函数或其他图型编写任务专用代码；不直接在模板目录执行。

函数图保存解析式、定义域、参数和采样规则；处理奇点、分段与断点，不能跨不连续处连线。统计图保存全部相关数据及过滤、聚合、缺失值、变换和误差定义。大点集优先栅格化点层、hexbin 或密度表达；抽样需要用户接受并披露。教学构造必须注明，不伪装成实验结果。

先设置最终物理尺寸，再排版与导出 PDF/SVG 和 PNG。更换字体或导出后端时，先用含实际中文、数学与上下标的小样检查目标文件的真实显示，有排版文件时再看嵌入页，确认后批量导出；字体已嵌入或文本可提取不能证明渲染正确。对可比面板共用坐标尺度或归一化。修图从代码和数据重绘，不让图像模型润色或重画定量面板。

## TikZ 路径

只作为简单框图的常规工具，或按用户要求维护已有 TikZ 图。复制 [TikZ 模板](templates/tikz_template.tex) 到任务目录，使用 [编译器](scripts/tikz_compile.py)：

```bash
python "$skill_dir/scripts/tikz_compile.py" figure.tex \
  --output-dir figures --formats pdf,svg,png
```

`skill_dir` 指当前 `SKILL.md` 所在目录，不假定特定安装位置。已有多文件 LaTeX 工程使用项目构建入口，不把章节或 `\input` 片段当独立文档。只检查所选路径需要的依赖；编译失败先修首个有效错误，不擅自修改全局环境或以缺包为由改变已选工具。

## 执行与交付

1. **建立简报与事实清单。** 记录核心问题及图上可见的答案、用途与最终尺寸、输出要求、必需对象与关系、原文标签、数据来源及不得推断的内容。先分清图内短标签与图注说明；已有信息充分时直接执行。
2. **选择表示并校准样张。** 先确定抽象层级、主阅读方向、面板职责及工具，将视觉取舍写成简短设计说明。系列任务在尚未解决的图型、密度或输出组合中选代表样张，按实际尺寸自检后复用样式与组件。已有合格样张或局部修改直接沿用，不机械增加候选或等待批准。
3. **生成并保留工作材料。** 模型路径保留事实、规划、提示词与版本；代码路径保留源文件和输入。数据与生成示意面板分别处理。
4. **查看实际产物并修订。** 逐对象、逐标签、逐边对照原材料，检查读者能否找到核心答案，再按设计说明检查整体与细节。按“位置—问题—修复—须保持”局部修改；框体、内容、端口与关联线一起核对。重复出现的问题先修共用组件，再检查受影响图片与实际页面。
5. **交付对应版本的核验结果。** 提供主文件、源代码或提示词记录、预览和具体限制；混合图保留面板原件与组合源。验收关联实际交付的文件版本及尺寸，区分本轮问题、已有问题和未检查范围；源、样式或排版在验收后改变时，重查受影响结果，不沿用旧版“全部通过”。

代码路径可运行：

```bash
python "$skill_dir/scripts/validate.py" \
  figures/figure.pdf figures/figure.svg figures/figure.png
```

模型 PNG 按最终嵌入宽度检查有效分辨率，例如：

```bash
python "$skill_dir/scripts/validate.py" figures/figure.png \
  --placed-width-mm 180 --min-dpi 300
```

`--placed-width-mm` / `--placed-height-mm` 使用像素与实际排版尺寸计算有效 DPI；与文件内的名义 DPI 分开。阈值按期刊与内容调整。验证器主要支持 PNG/PDF/SVG；其他栅格格式保留原件，另作无损 PNG 检查或使用能解码该格式的工具。脚本通过不证明标签、拓扑、数据或科学内容正确，仍须查看图片并对照源材料。

## 多轮工作与缺失信息

承接已确认的事实、风格、选定图片、源文件路径和具体缺陷。系列任务用一份紧凑记录区分通用规则、适用范围、局部例外及新增要求，不把新偏好倒算为旧图错误，也不把个别例外推广到整套图。常规取舍与修图持续推进；只有用户约定分阶段共创时才在选图点等待。连续修订无改善、工具失败或关键事实无法核实时，保留最佳版本与设计材料，说明具体问题，不把仍有科学错误的图称为完成或可投稿。

使用 `[待核实来源]` 标记无来源的机制或关系，`[待补数据]` 标记缺失数据，`[待作者确认]` 标记会改变图义的歧义。标记紧邻相关内容，不把待确认项包装成事实。

更新本技能或比较方法时使用 [设计评测](references/design-evaluation.md)。
