# 科技绘图

## 适用范围

本技能用于论文、学位论文、技术报告、教材和学术海报中的静态图片。可从文字、数据、草图或现有图片出发，创建、修改或检查图形。

不用于正文润色、纯统计分析、交互式仪表盘、演示文稿整体设计或普通美术创作。不得生成或修改可被误认为真实实验数据的显微图、医学影像、测量结果或其他证据。

开始前读取当前项目适用的论文、术语、版式和投稿规范。用户要求及目标期刊的最新指南优先于本技能默认值。

## 核心原则

- **先确定表达目标。** 用一句话写清读者看图后应理解什么，再确定图型、面板和工具。数据文件本身不是绘图目的。
- **图形承担解释。** 架构图和机制图先确定读者卡在哪一步，再选择能展示关系或变化的表示；不能把名词依次装进方框就视为解释完成。复杂图的设计方法见 [概念设计](references/concept-design.md)。
- **程序化工具优先。** 架构图、流程图和规则化示意图优先 TikZ；数据图优先 Matplotlib；只有具象且难以程序化表达的插画才使用图像模型。
- **科学内容不可补猜。** 不虚构数据、统计结果、模块关系、样本数量、箭头方向、因果机制、比例尺或实验条件。
- **颜色表达语义。** 配色随类别、顺序、发散或周期数据选择；颜色不能是区分对象的唯一线索。
- **图解默认样式。** 架构图、流程图和神经网络模块图默认采用青绿主色、蓝灰输入、墨蓝输出和赭橙训练或反馈信号；钢蓝和灰绿为备选，具体色值见 [视觉样式](references/visual-style.md#图解配色)。连线路由默认使用圆角正交折线，同轴相邻节点直接连接；优先遵守用户明确选择和项目已有的视觉约定。
- **按最终尺寸设计。** 字号、线宽、标记和间距在论文中的最终物理尺寸上检查，不靠导出后缩放补救。
- **可编辑和矢量优先。** 程序化图片保留源文件并交付真实 PDF/SVG；PNG 只作预览或承载真实栅格内容。
- **用缺陷驱动迭代。** 每轮修订针对可定位的科学、布局、标注、可访问性或输出问题，不用主观总分替代核验。

## 工具边界

### TikZ

满足以下任一条件时使用 TikZ：

- 关系、方向、层级或拓扑必须精确。
- 文字、公式、张量尺寸或箭头标签必须可编辑。
- 图形主要由节点、连线、分组、坐标轴或规则几何组成。

从 [TikZ 模板](templates/tikz_template.tex) 复制并重命名源文件。使用 [TikZ 编译器](scripts/tikz_compile.py) 生成输出：

```bash
python .trae/skills/academic-drawing/scripts/tikz_compile.py figure.tex \
  --output-dir figures --formats pdf,svg,png
```

编译失败时修复首个有效错误并重试。不得因为环境缺包就静默改用图像模型。

### Matplotlib

数值轴、统计量、数据点、分布、矩阵热图或函数曲线使用 Matplotlib。从 [Matplotlib 模板](templates/matplotlib_template.py) 复制并按图片主题重命名，不能在模板目录内直接执行。用于解释拼接、归一化或元素映射的小型数组与矩阵按机制示意图优先使用 TikZ，不因图中有数值就自动归类为数据图。

必须保留全部与问题相关的数据。过滤、聚合、缺失值处理、异常值处理、抽样和变换均需在代码和交付说明中记录。大规模点集优先栅格化点层、hexbin 或密度表达；只有用户接受且图注明示时才抽样。

### 图像模型

仅用于程序化图元难以表达的概念性科研插画。生成提示词必须包含对象、关系、构图、视角、背景、风格和明确禁项。

关键文字、公式、数值、比例尺和方向箭头不交给图像模型生成。优先生成无文字底图，再用 TikZ 或其他可编辑工具添加标注。保存提示词、模型、参数、版本和修改记录。

图像模型不得用于制造或替代实验数据、显微图、医学影像、观测图或定量结果。此限制不因时间压力、作者指示或是否披露而改变。

## 执行流程

1. **建立图片简报。** 写明核心信息、读者已有知识、理解难点和看图后应能回答的问题，以及用途、版面、必需对象、关系、数据字段和禁止推断项。
2. **选择图片类型和工具。** 对混合图逐面板路由。若用户已明确类型且输入完整，直接执行，不重复询问。
3. **设计解释结构。** 先确定抽象层级和图形表示，再安排阅读顺序、面板职责和视觉编码。复杂且结构未定的图，用真实标签和目标尺寸试排两到三种不同的解释结构，按科学内容覆盖和读者理解成本选择；常规取舍直接执行，科学信息缺失或取舍会改变结论时才询问。
4. **检查环境。** 探测 LaTeX、转换工具、Python 和 Matplotlib。缺少依赖时报告可执行的安装建议，不擅自修改全局环境。
5. **生成可编辑源文件。** 灰度草图就使用真实术语、关键对象状态和接近最终长度的标签；先解决内容、布局和布线，再应用语义颜色。沿用项目术语、颜色映射和版面尺寸，数据与绘图代码分离。
6. **渲染全部请求格式。** 程序化图默认生成 PDF、SVG、PNG；真实栅格内容至少保留原始分辨率。
7. **验证并修订。** 运行 [产物验证器](scripts/validate.py)，查看实际渲染图并按质量检查核验科学语义、读者理解和视觉效果。解释图要能从图上追踪一个具体输入、区分关系类型并回答简报中的问题；回答依赖未显示的源代码信息时，先修结构再调样式。
8. **交付。** 提供源文件、主矢量文件、PNG 预览、图注建议、必要的生成记录，以及未解决或待确认事项。

## 图片简报

内部使用以下字段，用户未要求时不机械展示：

```text
核心信息：
读者已知什么、卡在哪里：
看图后应能回答的问题：
图片类型与用途：
目标尺寸或期刊：
必需对象、关系或数据：
抽象层级与图形表示：
视觉编码：
不得推断的内容：
交付格式：
```

信息足以唯一确定图形时直接继续。缺少关系、数据字段、数量、因果方向或目标版面且不同选择会改变结论时，只询问一个最关键问题。

## 验证与交付

运行：

```bash
python .trae/skills/academic-drawing/scripts/validate.py \
  figures/figure.pdf figures/figure.svg figures/figure.png
```

脚本通过只证明文件结构和部分技术规格有效，不证明科学内容正确。最终还要人工或视觉检查标签、箭头、数据映射、遮挡、裁切、灰度可辨性和正文一致性。

不得把由 PNG 转封装得到的 PDF/SVG 称为矢量图。无法生成某种格式时，交付已验证的格式并明确原因，不伪造成功状态。

## 缺失信息标记

| 标记 | 使用场景 |
|---|---|
| `[待核实来源]` | 外部机制、标准、事实或关系缺少可核验来源 |
| `[待补数据]` | 作图所需数据、统计量、单位或实验信息缺失 |
| `[待作者确认]` | 布局取舍、术语、关系方向或目标范围存在多种合理选择 |

标记紧邻对应内容。正式交付前不得把带标记的内容表述为已经成立的结论。
