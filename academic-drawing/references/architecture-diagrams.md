# 架构图

## 适用范围

用于系统架构、模块关系、服务边界、数据流、控制流、软硬件协同和分层设计。默认使用图像模型生成完整图，按 [图像模型工作流](image-model-workflow.md) 规划、生成、校对和修订。只有少量节点、单层结构、短标签和简单连线组成的框图，才默认使用 TikZ；用户明确要求 TikZ 或局部维护已有 TikZ 图时沿用该路径。

本文件的独立标注层均为可选方案；用户明确要求模型原生文字时，保留原生文字并通过模型编辑修订，不擅自留白、覆盖文字或添加标注层。

不用于具有数值轴的数据图，也不把部署拓扑、调用关系和时序过程混在一张无层次的图中。

## 绘图前收集

- 核心结论和目标读者。
- 系统边界、外部参与者和内部模块。
- 每条连接的起点、终点、方向、载荷或协议。
- 同步或异步、数据或控制、正常或异常等关系类型。
- 必须保留的准确术语、缩写、版本和数量。
- 单栏或双栏宽度，以及是否需要与正文中的颜色映射一致。

缺少关键拓扑时标记 `[待作者确认]`，不得依据常见架构自行补全。

## 结构选择

| 结构 | 适用情况 | 阅读方向 |
|---|---|---|
| 分层 | 计算、存储、网络、应用等稳定层级 | 自上而下 |
| 管线 | 数据经过一系列处理阶段 | 自左向右 |
| 中心辐射 | 一个协调器连接多个同级组件 | 中心向外 |
| 泳道 | 需要区分参与者职责 | 泳道内顺序、泳道间交互 |
| 控制面与数据面 | 两类路径需明确分离 | 分区后各自保持单向 |

一个面板只使用一种主结构。若必须展示部署、请求路径和内部模块三个层次，拆成相邻面板或使用清晰的嵌套边界。

## 图像模型实现

把已核实的模块、边界和关系清单写进绘图描述，明确主阅读方向、模块分组、准确标签、各类线型与禁止新增的连接。短标签和箭头可以直接生成，不要求先做无文字底图。

查看生成图时逐节点核对名称与数量，逐边核对起点、终点、方向、载荷和边界。模型容易顺着布局补出不存在的中转路径，必须对照原始关系清单，而不是仅检查整体是否顺眼。复杂中文、长标签和公式难以稳定生成时，可选择预留标注空间并用可编辑 SVG 或 LaTeX 排版层添加；用户指定原生文字时继续模型编辑。不因此把复杂架构改成 TikZ。

## 简单框图的 TikZ 实现

下面的实现只示范简单框图和已有图的局部维护，不是复杂架构的默认画法。使用 `positioning` 做相对布局，使用 `fit` 绘制系统或层级边界，使用 `arrows.meta` 定义端点，使用 `calc` 处理连接锚点。

推荐语义：

```tex
\node[block] (ingest) {Ingestion};
\node[block, right=of ingest] (compute) {Compute};
\node[store, right=of compute] (storage) {Storage};

\draw[flow] (ingest) -- node[edge label] {records} (compute);
\draw[flow] (compute) -- node[edge label] {batches} (storage);
```

- 节点 ID 使用简短稳定的英文标识，显示文字沿用论文术语。
- 使用节点锚点连接，不用肉眼试出的绝对端点。
- 共享边界用 `fit` 放在背景层，不能遮挡节点和连线。
- 实际调用和数据路径使用实线，辅助连接通过线宽与深浅退后；异步、可选或其他关系只有在图中明确约定时才使用虚线。异常路径只有在图的目的需要时才出现。
- 连接标签仅在传递量或条件无法由结构辨认时保留短标识，不逐边描述动作或重复两端节点名称；过程读法放图注。

## 布局

- 先按 [构图与布局](composition-layout.md) 建立层、列或泳道网格；同层节点共享边缘、中心线或端口基线。
- 同层组件尺寸一致；确有信息层级时才放大核心组件。
- 先排节点再布线。连接交叉时优先重排节点，不先增加弯曲或跳线。
- 端口密集时为不同关系分配不同锚点，避免多条线完全重叠。
- 多条同语义连接共享起点或终点时，可合并为有明确分叉点的 `edge tree`；会掩盖独立关系或时序时不得合并。
- 连线路由默认采用统一圆角的正交折线样式，同轴相邻节点直接连接；分叉点保持线路连续，不为每条边单独试半径。
- 数据库、队列、外部系统等形状只在其语义明确时使用，不把形状当装饰。
- 容器边界表示真实所有权、部署或安全边界；图注解释边界含义。

## 常见错误

- **层级混杂：** 同一水平位置放置不同抽象层次。按层分区或拆图。
- **双向箭头滥用：** 请求和响应并不自动等于一个双向关系。必要时画两条有标签的单向箭头。
- **颜色代替边界：** 仅用颜色暗示模块归属。增加分组标题和边界。
- **图标过多：** 图标风格不一致并抢占标签空间。仅保留有识别价值的少量图标。
- **全图等权：** 所有框和线同样醒目。通过位置、留白和有限线宽差突出主路径。

## 验收

- 每个节点都能在正文或输入中找到依据。
- 每条有向边的起点、终点和标签均正确。
- 主阅读方向一致，交叉线和穿越节点的线已经消除。
- 系统边界、外部对象和内部对象可被无颜色地区分。
- 缩放到最终宽度后，标签、箭头和虚线仍清楚。
