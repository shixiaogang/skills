# 从概念到图形

用于架构、流程、网络和机制示意图。这里决定“画什么、怎样让读者理解”，[构图与布局](composition-layout.md) 再决定对象如何摆放。配色和圆角正交连线沿用 [视觉样式](visual-style.md)，不代替解释结构。复杂示意图默认用图像模型实现，按 [图像模型工作流](image-model-workflow.md) 把已确定的语义转成绘图描述；少量节点、单层结构、短标签和简单连线的框图才默认使用 TikZ。用户明确指定工具或局部维护已有图时沿用该路径。

## 找到理解缺口

先写出读者已知什么、容易误解什么，以及看图后应能回答的问题。例如，读者认识向量，却分不清拼接与逐元素相加；目标应是“能指出输出长度和元素如何形成”，而非“展示两个运算”。一个面板围绕一个可回答的问题，图题点明对象或机制，长段动机与边界放在图注或正文。

同时指出答案应该落在哪个可见关系上。两种方法若只更换标题、颜色或图标，流程仍几乎相同，先补出由材料支持的条件、处理对象或输出差异；尚不能在图上定位差异时不急于美化。草图阶段就区分必要变量与解释性公式：图内保留读者追踪关系所需的信息，推导、重复结论和长说明放到图注或正文；关键条件不可因精简而丢失。

把输入材料分成对象、对象状态、操作和关系。对关系写清起点、终点与含义，区分数据流、控制流、时间先后、归属和因果；这些关系不能共用一个未解释的箭头。用已有材料确定主机制，必要上下文退后。删去与问题无关的细节可以降低密度，但改变拓扑、条件或结论的删减需要披露，不能为了好看省略。

论文方法总览和复杂系统图按 [框架图设计](framework-diagrams.md) 区分语义对象与可见图元，并核对传递量的真实消费者。参考图只承担风格依据时，按 [参考风格迁移](reference-style-transfer.md) 提取视觉规则，不把参考中的模块或箭头带入当前机制。

## 根据问题选择表示

| 读者要弄清什么 | 优先尝试 | 图上应能看到 |
|---|---|---|
| 对象在哪里、属于谁 | 分层总览、泳道或真实边界 | 抽象层级、跨界关系、对象归属 |
| 一个输入如何被处理 | 数据流配关键中间状态 | 输入内容、操作、输出变化，必要尺寸 |
| 两种机制有什么不同 | 同一例子的对齐面板 | 固定输入，变化因素，输出差别 |
| 复杂系统中的某一步怎么工作 | 总览加局部展开 | 同名模块、输入输出端口、明确的放大对应 |
| 迭代到底更新了什么 | 单步反馈加前后状态 | 当前状态、反馈、更新规则、下一状态 |
| 条件如何决定下一步 | 判断、分支或状态转换 | 完整条件、分支去向、返回或退出位置 |
| 信息如何组合、选择或分配 | 对齐的数组、矩阵、集合或局部映射 | 元素对应、范围、索引或选择结果 |

这些是候选表示，不是固定题型模板。先问“哪个视觉关系能直接回答问题”，再选择形状。向量拼接适合保留元素顺序；权限边界适合显式容器；时序交互适合沿时间排列。若方框只承载名词、箭头只表示“然后”，需要补上关键变化，或换成更能显示机制的表示。

### 抽象层级与具体例子

总览只显示同级模块及跨模块关系；局部面板显示一个模块的内部机制。局部展开不是另一条运行分支，用面板标题、同名模块和无箭头的参考线建立对应。若同一对象重复出现，名称、状态和端口保持一致。

核心机制可以用一个小而完整的例子串起来：同一输入经过操作，得到可核对的输出。数值必须来自用户材料，或明确标为教学构造；无依据时只画准确的符号关系。该例子用于解释，不替代实验结果或一般性证明。比较机制时保持输入、布局尺度和命名一致，把变化集中在比较因素上。

用真实的元素、尺寸或局部变化表达信息，不为了每一步都出现而画满中间状态。取舍依据是：缺少该状态会不会让读者无法复核关键一步。

## 结构未定时比较草图

复杂且表达方式尚不明确的图，先做两到三种低成本草图。方案应在解释结构上不同，例如“全局管线”“总览加局部展开”“同例子的状态对照”；换颜色、圆角或左右顺序不算新的解释结构。输入完整的短流程、已确定的拓扑或小范围修改直接实施，不机械生成多个方案。

草图就采用目标宽度、真实标签和关键状态，可用文字布局、灰度简图或图像模型草图；设计线框不意味着成图必须用 TikZ。比较时回答：

- 必需对象、关系和条件是否都保留？有没有靠常识补猜的内容？
- 读者能否沿一条路径回答核心问题？是否要频繁跨面板寻找对应？
- 同级对象是否混入内部细节？哪个方案能减少无解释价值的框与线？
- 标签在最终宽度下是否放得下？长标签需要改布局或分图，不能靠缩小字体解决。

选择能完整表达机制且理解成本较低的方案，简短记录取舍后继续绘制。不为常规设计选择等待用户批准；只有缺少科学事实、需要改变表达范围或结论时才澄清。用户已指定表示或结构时遵从其选择。

## 用图例学习设计取舍

从 [对照图例](design-examples.md) 选一个与理解难点相关的案例，先查看实际预览，再读解释和所需源文件。借用它解决的理解问题，不照搬题材、节点数或布局。图例覆盖元素映射、抽象层级和状态更新；不要求每张图集齐这些形式。

修订现有图片时，先定位读者无法理解的步骤，再判断是缺状态、层级混杂、关系未区分还是布局拥挤。没有语义缺口的图可以只修样式；有语义缺口的图不能以上色替代重构。

## 方法来源与边界

围绕读者和消息设计图片、按实际媒介检查尺寸，参考 [Rougier et al., Ten Simple Rules for Better Figures](https://journals.plos.org/ploscompbiol/article?id=10.1371/journal.pcbi.1003833)。架构的层级分解参考 [C4 的图形层级](https://c4model.com/diagrams)；不强制把科研图改画成 C4，也不借此增加输入中没有的系统层。以上具体工作方法和配套图例是本技能的操作建议，效果需通过真实任务验证。
