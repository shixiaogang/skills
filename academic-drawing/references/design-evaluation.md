# 设计能力的回归评测

用于修订本技能或比较设计方法。普通绘图交付按 [质量检查](quality-checklist.md) 验收，不要求每次运行整套评测。

## 比较方式

固定输入事实、读者背景、目标尺寸和可用工具，保留旧版与新版技能的提示、源文件、渲染图和时间。复杂更新宜用独立执行者完成真实任务；不要提前告诉它应该选哪种布局，也不要把预期答案混入绘图提示。比较图上能否回答问题，而非文字是否提到“层级”或“理解”。

先核对科学事实，再看实际渲染图。记录核心问题的答案及对应视觉证据、理解断点、错误关系和可读性问题；技术导出另行检查。错误关系不能由美观抵消。单次成功只说明该任务可执行，不证明整体质量提升；需要重复任务或读者反馈才能支持更广泛结论。

## 固定用例

| 用例 | 给执行者的完整事实与任务 | 观察重点 |
|---|---|---|
| 元素映射 | 给刚认识向量的读者，比较 `x=[1,2]`、`z=[3,4]` 的拼接与逐元素相加；结果分别为 `[1,2,3,4]`、`[4,6]`。宽度180mm，图注说明教学数值。 | 不混淆运算；能从图定位第三个拼接元素和第二个相加元素的来源；固定同一输入。 |
| 总览与内部 | 查询经搜索到回答；搜索内部依次编码、检索、重排，语料库连接检索。给初学者同时解释系统职责和搜索内部过程，宽度180mm，明确为指定的教学系统。 | 抽象层级可辨；语料库端点正确；重复展开的模块可对应；放大关系不冒充数据流。 |
| 单步更新 | `L(w)=(w-3)^2/2`、步长0.5、当前值1、梯度-2、下一值2。解释梯度下降这一步更新了什么，宽度180mm。 | 当前/下一状态可辨；更新依赖当前值与梯度；计算可复核；不凭单步示意声称收敛。 |

这些任务已有配套 [图例](design-examples.md)，适合检查资源是否可用，不能作为独立的泛化证据。

## 未配图任务

测试时只把下列“任务输入”交给执行者；评审者再使用“观察重点”。根据已有失败案例扩充题目，避免只检查三种已提供的布局。每次发布保留一部分没有用来修订规则的新任务。

### 任务输入：缓存查询

给理解函数输入输出但没学过缓存的读者，解释一个缓存的两种路径。键 `k` 进入缓存查询；命中时直接返回缓存值 `v`；未命中时运行 `f(k)` 得到 `v`，写入缓存后返回 `v`。写入完成后返回是本例的既定顺序。宽度120mm；不要补充淘汰、并发或一致性策略。交付可编辑源和预览。

观察重点：命中与未命中分支覆盖完整且不混淆；命中路径绕过计算和写入；未命中计算、写入、返回的顺序可追踪；没有猜出额外策略。评审还要看读者能否说明“两条路径返回同类值，却经历不同工作”。

### 任务输入：同一矩阵的不同归一化

给认识矩阵但不熟悉归一化的读者，解释对矩阵 `[[1,3],[2,2]]` 分别按行和按列除以对应行和或列和。按行结果为 `[[1/4,3/4],[1/2,1/2]]`，按列结果为 `[[1/3,3/5],[2/3,2/5]]`。宽度160mm，明确是教学构造。不要把它描述为 softmax，不要求完整算法流程。

观察重点：同一输入可辨；归一化范围和分母来源可见；能复核任一位置及行和/列和；不因为题目含有“处理”就全部画成名词框。图形不必采用预定布局，能回答问题即可。

## 结果记录

对每个任务记下：输入版本、采用的表示、核心问题是否可由图回答、具体缺陷、技术检查、耗时与未解决限制。使用 `PASS`、`PASS WITH WARNINGS` 或 `FAIL`，依据质量检查中的阻断项；不输出未经定义的审美总分。只根据观察到的失败修订规则，避免把一次任务的布局偏好变成所有图片的强制步骤。

方法参考 [OpenAI：Testing Agent Skills Systematically with Evals](https://developers.openai.com/blog/eval-skills)。这里的用例和阅读检查是本技能自建的评测材料；自动技术校验不能替代解释效果评审。
