# 框架图评审（diagram-review）—— 流水线第 ③步

讲框架图的验收：三条独立通道（科学准确、读者理解、视觉质量 + 样式对齐），分别检查，不能用平均分抵消问题。仅查源码或提示词不构成成图验收——必须对实际渲染出的图片打分。

第 ①步设计稿见 [diagram-model](diagram-model.md)；第 ②步 TikZ 还原见 [diagram-tikz](diagram-tikz.md)；评审时**两张图都要在手**：

- `drafts/figure-draft.png`：图像模型出的设计稿（气质参照）。
- `figure.pdf` + `figure.png`：TikZ 还原后的最终交付图。

数据图走 [chart-review](../chart/chart-review.md)。

## A. 科学准确

- 图的核心信息能用一句话陈述，且与正文和图注一致。
- 图中对象、关系、箭头方向、数量、单位和符号均有输入或来源支持。
- 事实、推断、假设和示意内容可区分。
- 图像模型生成内容明确是概念示意，不会被理解为实验或观测证据。
- 模型图的每个标签逐字与原文标签表核对，中文、数字、上下标、维度和运算符没有近似误写；未把字体外观近似宣称为真实字体嵌入。
- 逐条在实际图中定位关系清单的起点、终点、方向、条件与线型，再反向核对图上每条连接均有依据；没有多余边、错接端点、伪双向、假中转或重复模块。
- 只迁移参考图的风格时，没有引入参考图特有的模块、分支、变量或数据。
- 未解决的 `[待核实来源]`、`[待补数据]` 和 `[待作者确认]` 没有被包装成结论。

**阻断项**：虚构证据、错误关系、错误数值、错误单位、无法解释的数据变换。

## B. 读者理解

查看最终尺寸的实际渲染图，暂不借助绘图源文件；图注可以提供定义、条件和范围，但关键关系应能在图上指出。

- 回答图片简报中的读者问题，并指出答案对应的对象、路径、状态或面板。
- 沿一个具体输入追踪其变化：进入哪里、经过什么操作、产生什么输出。若图旨在表达边界或归属，则改为核对一个对象的所属范围与跨界关系。
- 区分箭头表示的数据、控制、训练反馈、时间或局部放大；不能只凭"应该如此"的领域常识回答。
- 对比图能指出改变的因素和保持不变的条件；循环图能指出更新对象、返回位置，以及流程所需的退出条件；局部展开能对应到总览中的准确模块。
- 机制依赖尺寸、顺序、索引或对象状态时，这些信息可见；不只展示操作名称。
- 核心机制通过正确对象、算子、结构和连接呈现输入到输出的变化；结果图元没有替代缺失操作。
- 执行对照中的通过、失败、主动跳过、未到达和未知按证据区分，终止后的步骤没有继续显示执行箭头。
- 结构对照中的同一对象可对应，增删与端点变化可定位，未把重新排版或线路绕行误称为系统变化。

把问题记录为"图上哪里导致什么误解"，优先补状态、调整抽象层级或更换表示，再修间距和配色。

**阻断项**：无法回答核心读者问题、关键变化只能从源代码猜出、不同关系被误读为同一种关系、跨面板无法对应对象。

## C. 视觉质量

### C1. 七个评议维度

与所选参考并排比较相同维度；没有复制参考色值或圆角，不构成失败。

| 维度 | 在实际图上判断 | 较好表现 |
|---|---|---|
| 整体构图 | 是否有完整的形态和自然的阅读组织，还是临时拼接的框与文字 | 节点组按阶段或功能横向并列；标题可选、不喧宾夺主；底部可接图例或时间轴 |
| 比例与视觉重量 | 主机制是否获得足够面积，局部轻重是否协调 | 主流程节点比辅助节点稍大；标题比描述大半档即可；节点如带图标，图标占 25-40% 高度 |
| 留白与节奏 | 组内与组间是否有秩序，是否局促或松散 | 节点间距统一（10-14 mm），组内对齐严格；画布四周 10-14 mm 留白 |
| 层次与对比 | 重点、对照关系与上下文是否清楚，有无相互争夺注意 | 字号层级 3-4 档；关键步骤用 Lancet feedback 色强调；编号圆点标明阅读顺序 |
| 文字与图形 | 标签是否自然融入对象，字形、换行和尺度是否协调 | 节点标题用思源黑体 Medium，描述用霞鹜文楷灰色；边标签与 badge 不互相遮挡 |
| 色彩与视觉语言 | 配色是否有组织，同类元素是否来自一致的设计 | 节点按角色取 Lancet 2024-07 语义色；若带图标，图标与描边同色（不是黑色）；填色与描边成对出现 |
| 细节完成度 | 端点、边距、文字基线和裁切是否稳定 | 箭头都是中性深灰实心 Latex 大头；节点等高对齐；若使用图标，线宽统一 |

可用"弱／可用／出色"附具体视觉证据，不计算审美总分。标出最影响质量的少数维度，并给出改善方向。没有错字或交叉不能证明美观。

### C2. 必备细节

- **无游离注解**：所有标注都贴附在具体节点、连线或分组上；没有脱离元素的大标题、游离小标签、底部图例条、作者戳。能靠节点与色彩自解释的信息一律不另写文字。
- **节点标题 + 描述齐备**：节点有节点标题和一行描述；单纯一个标题的节点视为缺失。图标**可选**：加了就统一风格、与描边同色，不加也没问题。
- **颜色承担语义，不装饰**：每种色相都能被读者立刻映射到角色；相同角色跨图保持相同色相。默认走 Lancet 2024-07 调色板。
- **字重轻盈**：节点标题用思源黑体 Medium，描述用霞鹜文楷灰色，不用 Bold / Heavy 字重，不追求"工业粗壮"。
- **流程线明确且少交叉**：主流程是实心细 Latex 箭头，中性深灰；分支/可选用虚线；禁止彩虹箭头。
- **编号圆点标步骤**：顺序超过 3 步时贴 4-6 mm 实心圆点；badge 与边标签不重叠。
- **图标风格统一**：若使用图标，全图图标来自同一图标集。
- **装饰克制**：阴影、渐变、磨砂玻璃、斜 3D 一律默认关闭。

### C3. 连线逐边核对（代码图尤重）

每条有向连线按下列项逐条核对；多节点正交布线、修订后搬移过节点位置、或改变节点锚点时必查。只核对编译通过和总体感不足以替代。

- **起点与终点锚点**：是否按预期的方位（west/east/south/north）发出和进入？进节点角点时的最后一段路径是否真的是水平/竖直？想要水平入时最后一段的 y 是否等于入点的 y？
- **中段走廊**：每段的 x 或 y 是否按设计走指定走廊？在同一走廊是否有多根线并排、相隔是否足以视觉区分？
- **穿越检查**：路径有没有穿过非目标节点或遮挡其他线的标签？移动过任一节点后，是否重查**所有**穿过该节点新 y/x 坐标的横线和竖线？
- **风格统一**：同类主线是用对角直线还是正交折线？是否与整图其他连线一致？
- **多线共端点**：一个节点有多条进/出线时，是否分配到不同锚点或显式偏移，视觉上不堆叠在同一点？

修补一处布线后，重查**整图所有相关线**，不只检查当前这一条——节点新 y/x 常使另外几条已存在的横/竖线穿到它上面。

### 不作为失败理由

不以某种色相、曲线、尖角、字重、非对称或多个对等主体作为失败理由。参考里的弱点不继承；用户认可的优点作为保留项。整体问题允许模型重新设计，局部问题按范围编辑；不能为视觉平衡改变科学事实或数据尺度。

**阻断项**：关键文字不可读、箭头归属不明、有效路径遮断、关键元素裁切、无法追踪核心关系。

### C4. 样式对齐（TikZ 还原 vs 设计稿）

把 `drafts/figure-draft.png` 和 `figure.png` 并排放，核对气质是否一致：

- **调色板**：节点底色、描边、强调色是否沿用设计稿的色系（统一走 Lancet 2024-07 或用户指定色板），不是把设计稿退化为灰阶学术线稿。
- **字重与节奏**：节点标题是否轻盈的思源黑体 Medium（而非粗黑），描述是否霞鹜文楷灰色；行距、字号层级与设计稿一致。
- **节点形态**：圆角半径、描边粗细、填色比例、是否带图标与设计稿一致；若设计稿有图标，TikZ 还原应保留或换成同色相的矢量图标。
- **留白节奏**：组内与组间间距比例一致；没有因为"把 PNG 嵌到 TikZ"而留出可见的硬边框或空白缝隙。
- **混合渲染衔接**：若用 `\includegraphics` 嵌入设计稿裁剪或模型补生成的 PNG，看接缝处是否自然；嵌入片段的笔触、色彩、线宽与整图一致，不出现"左半张卡通右半张工业线稿"的割裂。
- **信息完整性**：设计稿里的每一个节点、连线、分组、关键文字标签都在 TikZ 还原里有对应（允许用图标代替装饰图元，不允许静默丢失事实元素）。

**阻断项**：TikZ 还原丢失设计稿的核心信息、调色板彻底换成另一套、混合渲染接缝生硬到读图断裂、字重 /节奏显著偏离设计稿导致"看起来是两张图"。

## D. 文件与技术输出

- TikZ 还原图的 `.tex` 源文件存在、可独立编译；嵌入 PNG 的 `assets/` 完整、路径相对正确。
- 设计稿 PNG、prompt、模型参数、工具版本保留在 `drafts/`。
- 程序化线稿有真实 PDF 或 SVG 主文件，不是位图转封装。混合渲染时在图注或 README 中说明哪些部分是栅格嵌入。
- 模型栅格按原始像素与最终嵌入尺寸计算有效 DPI，不依赖名义 DPI 标签。`scripts/validate.py` 的 `--placed-width-mm` / `--placed-height-mm` 用于 PNG 嵌入尺寸；未因指定两维尺寸拉伸图形。
- PNG 预览存在、非空白、未裁切，并满足目标清晰度。
- 若交付 PDF，页数与物理尺寸正确，可嵌入的字体已嵌入或采用期刊允许的处理；包含栅格嵌入时明确其组成。
- 实际渲染目标 PDF/SVG，检查中文、数学与上下标完整显示；字体嵌入、文本提取或 PNG 预览正常都不能单独证明目标文件正确。
- 若交付 SVG，有效 `viewBox` 与尺寸完整，文字处理符合要求；SVG 内嵌 PNG 不能称为纯矢量。
- 真矢量与可编辑文字分开核验：字形轮廓是矢量，但不是可直接改字的文本。
- 栅格图没有通过上采样伪造分辨率。
- 明确要求纯矢量时，整图的对象和字形实际为矢量，保留可编辑源。
- 使用 `scripts/validate.py` 检查全部支持的图形文件；警告项人工确认。

验证命令：

```bash
python "$skill_dir/scripts/validate.py" \
  figures/figure.pdf figures/figure.svg figures/figure.png
```

**阻断项**：文件打不开、空白输出、尺寸错误、字体丢失、伪矢量、伪造 DPI。

## E. 上下文与交付

- 图内术语、缩写、变量和正文一致。
- 图注与正文中的颜色、对象名称和视觉解释已随修改同步；解释性长句没有为了省图注而挤回图内。
- 嵌入书稿或论文时查看实际完整页面，核对文字、图注、边注、裁切和阅读顺序。
- 节点名、边标、内部短标识和图注定义各有职责；内部 ID、文件路径、候选编号及检查字段未泄漏到正式图内。
- 合并、折叠或省略语义内容时有源对象/关系到图面、局部展开或说明的映射。
- 外部素材的来源、许可和修改情况可追溯。
- 图像模型路径保留提示词、模型、参数、时间和迭代记录。
- 模型与参数只记录工具实际提供的内容；未暴露的字段明确注明，未猜测版本、种子或质量。提示词支持重生成，不承诺像素级复现。

## 最终结论

按实际检查范围给出结论：

- `PASS`：科学与技术核验通过，读者问题可回答，设计达到当前目标。
- `PASS WITH WARNINGS`：可用且无科学或阅读阻断项，存在明确列出的非阻断限制。
- `FAIL`：存在阻断项，或设计尚未达到任务目标。

没有实际成图时只能报告规划或规则检查结果；没有实际前后比较时不能报告视觉质量提升。
