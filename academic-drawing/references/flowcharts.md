# 流程图

## 适用范围

用于算法步骤、处理管线、状态转换、决策逻辑和可重复工作流。默认使用 TikZ。

流程图表达控制或处理顺序，不替代系统边界图、时序图或数据统计图。过程包含多个参与者时，优先使用泳道或拆分为流程图与架构图。

## 绘图前收集

- 明确起点、终点和正常主路径。
- 列出动作、输入输出、判断条件、循环条件和异常路径。
- 确认哪些步骤可并行、哪些步骤有严格先后依赖。
- 确认判断分支的完整条件和汇合位置。
- 保留论文中的准确术语和算法符号。

## 图形语法

| 含义 | 形状 | 连接 |
|---|---|---|
| 开始或结束 | 圆角终止框 | 一条主路径 |
| 处理步骤 | 矩形 | 动词短语 |
| 输入或输出 | 平行四边形或明确标注的矩形 | 写清对象 |
| 判断 | 菱形 | 每个出口标注条件 |
| 子流程 | 双竖线矩形 | 名称与正文一致 |
| 数据存储 | 圆柱或存储框 | 仅用于持久化对象 |

形状语义在整张图中固定。若受版面限制不能使用特殊形状，可统一用矩形，但必须通过标题或前缀明确“判断”“输入”“输出”。

## 布局规则

- 先按 [构图与布局](composition-layout.md) 建立主轴、分支列和外侧回路带，使用共享间距尺度区分主流程与异常路径。
- 主路径自上而下；横向布局只用于短且严格线性的管线。
- 判断后的首选或成功路径保持直行，异常和退出路径向侧面分支。
- 分支条件放在离开判断节点的边上，例如 `yes/no`、`hit/miss`、`valid/invalid`。
- 回路从外侧以正交折线和统一圆角返回，不逆向穿过主流程。
- 并行步骤使用显式 fork/join，不用视觉并排暗示同步。
- 一个节点只表达一个动作。标签优先采用“动词 + 对象”，避免完整说明段落。

TikZ 示例：

```tex
\node[start] (start) {Input};
\node[process, below=of start] (check) {Validate schema};
\node[decision, below=of check] (valid) {Valid?};
\node[process, below=of valid] (run) {Render figure};
\node[process, right=of valid] (fix) {Report mismatch};

\draw[flow] (start) -- (check);
\draw[flow] (check) -- (valid);
\draw[flow] (valid) -- node[edge label] {yes} (run);
\draw[flow] (valid) -- node[edge label] {no} (fix);
```

## 语义检查

- 每个判断节点至少有两个互斥出口。
- 分支条件覆盖所有可能情况，不能两个出口都写模糊的“其他”。
- 循环具有终止条件。
- 状态转换只画合法迁移；不把时间顺序误画成因果关系。
- 删除不会改变流程含义的装饰步骤。

## 常见错误

- **流程和数据流混用：** 相同箭头同时表示“下一步”和“传递数据”。拆分线型并添加标签。
- **菱形内写动作：** 判断节点应是可回答的问题或条件。
- **线条交叉：** 先调整节点顺序和分支方向，再考虑跨线桥。
- **大量回线：** 说明流程层级过深。抽取子流程或拆成两个面板。
- **编号与箭头重复：** 线性流程已有清楚箭头时不再添加无意义序号。

## 验收

- 从起点沿任一分支都能到达终点或明确的循环。
- 判断出口均有条件标签，条件与正文一致。
- 箭头方向、汇合点和回路没有歧义。
- 只看灰度和线型仍能区分主路径、异常路径和参考关系。
- 缩放到最终尺寸后，最短箭头和分支标签仍清楚。
