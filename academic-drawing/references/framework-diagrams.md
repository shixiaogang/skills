# 论文框架图与方法总览

用于方法总览、复杂模型架构、算法机制和系统交互图。默认按 [图像模型工作流](image-model-workflow.md) 生成完整图，结合概念设计、对应图型和质量检查使用。少量节点、单层结构、短标签和简单连线的框图可用 TikZ；用户明确要求 TikZ 或局部维护已有 TikZ 图时沿用该路径。短流程与单纯样式修改不需要额外表格或阶段。

## 选择解释主线

先写一句读者看图后应能回答的问题，再按论文或教材真正要解释的对象组织画面。

| 解释重点 | 主线候选 | 要直接看到的变化 |
|---|---|---|
| 方法或训练策略 | 操作序列、反馈循环 | 哪一步改变了选择、约束或更新 |
| 模型架构 | 模块与层级 | 模块如何配合，输入输出怎样衔接 |
| 系统或协议 | 角色交互 | 谁向谁传递什么，何时发生 |
| 参数、记忆或状态 | 当前状态—操作—下一状态 | 更新对象、依据与结果 |
| 数据建设、检索或处理 | 数据管线 | 来源、加工、筛选与去向 |
| 评价或基准 | 评价协议、对照结构 | 对象、条件、指标与比较口径 |

这些是选择依据，不是排他分类。架构图可以用数据流组织模块，只要它能解释核心机制；不能仅因存在输入数据，就把所有图强行画成同一条处理管线。背景、例子和图例应支持主线，面积和字重不能盖过核心机制。

## 分开记录科学语义与可见图元

语义记录可以包含模块、角色、数据、变量、状态及其依赖。可见图形只需要让读者理解当前问题的部分。

- **模块或操作**：具有明确计算职责、输入输出或所有权边界，适合主节点。
- **传递量**：特征、梯度、权重、阈值、分数及中间状态，优先标在真正对应的边、端口或汇合处。
- **需要观察的对象**：矩阵、样本、缓存项、概率分布、前后状态，可以独立画出；其存在须帮助读者核对操作，不能与所有模块机械并列。
- **补充定义和条件**：移至图注或正文，保留理解机制必需的短标识。

变量可以有独立图元。例如重参数化、矩阵映射和状态更新教学图需要看见变量或数值本身。选择依据是解释任务，不能把“变量放在线上”当成所有图片的硬规则。

复杂图可使用下面的紧凑记录；只记录当前任务需要的字段，不要求全部写成 JSON。

```text
读者问题、主线、最终尺寸：
语义对象：名称｜职责或状态｜材料中的位置
可见对象：对应语义对象｜模块/对象/边标/图注｜选择理由
关系：起点与端口｜终点与端口｜传递量或关系｜方向｜证据
核心操作：输入或上下文｜操作与位置｜输出或变化
必要可见文字：准确短标识｜对应元素/边/端口｜删除后会产生的歧义
图外说明：图注中的读法和条件｜正文中的推导；重复内容删除
线型约定：线型｜一个关系含义｜对应端点
禁止误画：当前材料中容易被反转、错接、重复或混淆的关系
```

内部节点 ID、候选编号、文件名和检查字段不出现在正式图内。语义记录、图形源文件、绘图提示词与图注使用同一套名称；有冲突时先修设计说明。

## 逐条核对连接

每条重要连接核对起点、终点、方向、传递内容及依据。证据可来自正文段落、公式、算法步骤、代码或用户给出的教学事实。推断关系记录其前提，不能把“常见做法”当成当前材料的事实。

特别检查图形布局造成的假中转：若 A 产生 `x`、C 使用 `x`，而 B 不接收、不改变也不路由 `x`，即使 B 摆在中间，也不能画成 `A → B → C`。应连到真正的 C 输入端，或在图注解释该依赖。若 B 确实存储、过滤或路由了 `x`，则按原机制保留中转。

同起点、终点、方向和含义的连接可以合并成主干，只有需要辨认传递量时才加短标签。不同量、不同时间、独立连接或需要逐个对应的几何映射应保留；不能为了减少线条，抹掉它们的区别。

数据流、控制流、反馈、无向关联和局部展开各自有明确画法。虚线不用于随意填空；同一线型的含义不能在一图内来回变化。放大参考线通常用无箭头的细中性线或括号，不画成新的计算分支。

## 展示核心操作，而非只有结果

每个必须解释的机制，在正确的模块、层、阶段或循环处保留可见对象、操作与结果。下面是设计者核对关系的思路，不是要写在图内的三个阶段标题或过程句：

```text
输入/上下文 → 操作/改变 → 输出/效果
```

矩阵图应能指出元素如何形成，筛选图应能指出选择条件，更新图应能指出谁依据什么被改变。只画输出矩阵、状态点或损失值，不等于解释了产生它的操作。

核心复合模块可以显示少量简洁图元，例如选择门、合并点、局部矩阵映射或一次状态变化；图元来自已核实机制。无须给每个常规模块都添加图标或微型算法，空框可以承担已经清楚的接口职责。

需要细节时选择一种表达：在主模块内展开，或在主图保留抽象模块并用独立面板展开。后一种方式要通过同名模块或锚点明确对应；细节面板必须增加信息，不能与主模块重复同一条内部流程。

## 重复对象与版面密度

多个客户端、样本、视角或条件如果使用相同机制，可用一组实例、括号、索引或省略号表达。只有真实分支、不同操作、需要比较的对象或数量本身重要时，才展开完整流程。不要把“体现异质性”直接解释成每个角色各画一条重复管线；先说明差异具体发生在哪一步。

紧凑指相关元素靠近、层级清楚且路由有序，不指把画布填满。核心机制获得主要空间；背景缩成必要的输入、边界或局部上下文。出现碎片化小框、大片无用空白或抢眼背景面板时，先合并抽象层级、调整阅读路径，再改字体或颜色。不用固定面积百分比或模块数量代替实际尺寸检查。

## 候选与缺陷修订

只有表达结构尚未确定或用户要求比较时才做候选。候选的差异应落在读者问题、阅读路径、抽象层级或机制表示上；各候选使用同一组事实。选定方向后，保存有用的局部特征，并修复已发现的语义错误。

问题记录使用“位置—误解—修复”，例如“编码器右侧的虚线像数据流，读者会把局部展开当成并行分支；改成无箭头参考线”。检查语义记录、绘图描述或源文件，以及实际渲染图，修复未支持箭头、变量冒充模块、假中转、操作缺失、细节重复、符号混淆及标签矛盾，再继续交付。

长期或多轮任务把确认过的事实、风格选择、生成提示与资产路径、可编辑源文件路径、候选来源与未解决问题保存在项目中。只有用户需要跨会话恢复包时才打包；恢复包应包含生成记录、适用的源文件、数据和引用资产，不能只保存最后一张图。
