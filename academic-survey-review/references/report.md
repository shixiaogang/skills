# 评审报告

报告服务于作者定位和修复高影响问题，不用于展示检查工作量。默认不输出完整底稿，但所有结论必须能追溯到底稿中的文章位置或外部来源。

## 严重程度

| 级别 | 判定标准 |
|---|---|
| 阻断性 | 使主要结论不成立、造成实质误导，或使综述范围和证据无法判断 |
| 主要 | 明显削弱覆盖、分类、演进、综合或可理解性，需要结构性修改 |
| 次要 | 不改变主要判断，但会影响准确性、清晰度、一致性或图表使用 |

不要按修改工作量定级。一个容易修正的错误可能是阻断性的，一个改动很大的风格偏好也可能不重要。

## 分维度结论

结论只使用：

- `通过`：证据充分，未发现影响该维度成立的重要问题。
- `部分通过`：主体成立，但存在明确且重要的缺口。
- `不通过`：核心要求未满足，或现有内容造成实质误导。
- `无法核验`：材料、上下文、工具或外部证据不足。

四个标签是原子状态，不追加第二个结论。例如不要写“无法核验，但疑似不通过”。若已提供的原文或明确事实足以证明核心缺陷，使用“不通过”并在限制中说明上下文不足；若只知道风险而不能确认缺陷，使用“无法核验”。

判定受以下证据门槛约束：

| 结论 | 最低证据要求 |
|---|---|
| 通过 | 对应材料完整，适用检查已完成，且没有重要反证 |
| 部分通过 | 已有正面证据，同时存在可定位的重要缺口 |
| 不通过 | 送审材料中存在可定位、足以破坏该维度核心要求的缺陷 |
| 无法核验 | 对应材料未提供、检查未执行，或只有不能支持判断的间接描述 |

缺少某一维度的材料不能作为该维度“不通过”的证据。一个维度中的问题也不能自动决定其他维度；例如分类错误不自动证明演进或洞察不合格。

用户、编辑或任务描述中的“文字流畅”“结构清楚”“分类合理”等概括，只用于记录送审背景，不是该维度的正面证据。未直接看到相应正文、分类或图表时，判为“无法核验”，不能仅凭这些二手评价判为“部分通过”或“通过”。

置信度只使用“高、中、低”。它表示对该维度实质质量判断的置信度，不表示对“材料缺失”这一事实的确信程度：

- `高`：关键材料完整，主要证据已直接检查并完成必要交叉核验。
- `中`：有原文片段或任务明确给出的直接事实，但上下文、检索或抽查范围有限。
- `低`：信息稀疏、来自二手描述，或关键核验尚未执行。

“无法核验”固定使用低置信度。不要在总括句声称所有维度均为某一置信度，却在明细中填写其他等级。

对于完整评审以及结构或分类定向评审，“结构与文字表述”和“分类整理”的通过判定还受
结构一致性门禁约束。只有在底稿中完成同级职责矩阵、主要论证链以及适用图表的行列依据检查，
才能判为通过。目录整齐、段落顺畅、各项技术陈述分别正确或比较表已经成形，都不能替代这些证据。

若检查发现同级单元混用论证阶段、案例、表示层级或证明方法，应按影响报告：

- 读者无法还原主要论证怎样组成，或分类表形成错误父子关系时，通常属于主要问题。
- 混列进一步导致概念误同、比较结论失效或总体结论误导时，可以属于阻断性问题。
- 仅标题不够准确，而正文职责和关系清楚时，才可能属于次要问题。

完整评审使用七个维度：

1. 结构与文字表述。
2. 图表呈现。
3. 内容与论证正确性。
4. 全面性与无偏性。
5. 演进脉络。
6. 分类整理。
7. 深度理解与洞察。

定向评审只报告用户请求的维度及其范围限制，不对其他维度填充“无法核验”，也不给全文总体通过或不通过结论。

## 默认输出结构

```markdown
# 综述评审

## 评审范围与限制
[版本、范围、材料、检索条件、重要限制]

## 总体判断
[当前质量、最重要的两到四个问题、总体处理建议]

## 主要发现

### [R1] [问题标题]
- 严重程度：
- 维度：
- 位置：
- 问题：
- 证据：
- 影响：
- 建议：

## 分维度结论

### 结构与文字表述
- 结论：
- 置信度：
- 主要证据：
- 主要缺口：
- 修改优先级：

[其余六个维度使用相同字段]

## 关键遗漏与相关工作建议
[只列会改变领域地图或主要结论的资料，并说明原因]

## 修改顺序
[按依赖关系排列修正工作]

## 核验声明
[已核验、抽样核验、未核验内容，检索日期与证据限制]
```

完整评审篇幅较短时可以压缩标题，并将七维结论合并为一行或紧凑表格，但不能省略范围限制、七维判定、置信度和核验声明。定向评审保留所请求维度的结论、置信度、证据和限制。

## 发现的写法

每条发现必须包含：

- **位置**：章节、页码、段落、公式、图表或可定位引文。
- **问题**：陈述可验证的差距，不使用“感觉不够深入”等空泛评价。
- **证据**：文章内部矛盾、推导、外部来源或材料缺失。
- **影响**：说明它如何影响理解、正确性、覆盖、分类或结论。
- **建议**：给出最小可执行的修正方向，不替作者虚构内容。

相同根因合并。例如分类维度混杂导致多个章节重复时，报告一个分类框架问题，并列出主要受影响位置。
如果正文标题和比较表共同重复同一层级错误，也应合并为一个根因，但分别列出正文与图表证据。

## 关键遗漏

将候选资料分为：

| 类型 | 使用条件 |
|---|---|
| 确定遗漏 | 在声明范围内，且会改变主要分类、历史判断或结论 |
| 建议补充 | 能加强代表性、对照或边界，但不改变总体框架 |
| 延伸阅读 | 超出当前必要范围，仅帮助继续研究 |

每项资料说明“补充什么缺口、可能改变什么判断”。不要输出没有解释的长书目，也不要把所有检索结果都列为遗漏。

## 修改顺序

默认按依赖关系排序：

1. 修正事实、定义、逻辑、证明和结论边界。
2. 明确研究问题、范围和选材依据。
3. 补齐关键相关工作并处理偏差。
4. 重构演进、分类和跨文献综合。
5. 调整章节、段落和图表。
6. 统一术语并润色中文表达。

具体文稿可以调整顺序，但不得先用润色掩盖正确性或范围问题。

## 受限结论措辞

使用精确的范围说明：

- “在已提供章节中未发现……”而不是“全文不存在……”。
- “在本次检索范围内未发现……”而不是“该领域没有……”。
- “现有材料不足以确认全面性”而不是直接断言“遗漏严重”。
- “摘要明确声称……”而不是把摘要内容当作已核验的方法细节。
- “该图表尚未提供，无法核验”而不是假设图表存在具体缺陷。

## 改写请求

用户只要求评审时，不直接重写正文，可提供必要的局部示例说明修复方向。用户明确要求修改时：

1. 先交付或确认评审发现。
2. 使用 `academic-writing` 修改已确认范围。
3. 修改后重新核对事实、条件、引用、图表和上下文。
4. 不把评审者提出的新观点伪装成作者已有结论。

只有取得待改原句、公式或图表内容时，才给出可直接替换的版本。若用户只描述问题而未提供原文，说明必须保留和收窄的语义条件，不补造变量、公式、图号、数据口径或不存在的段落。

## 交付前检查

- 高影响发现是否排在前面。
- 每条发现是否有位置、证据、影响和建议。
- 七个维度是否都有结论、置信度和限制。
- 结构或分类判为通过前，是否完成同级职责矩阵、论证链和适用图表的独立分类检查。
- “通过”是否有充分证据，而非仅仅没有看到错误。
- 关键遗漏是否真正影响领域地图或结论。
- 外部来源是否按实际访问层级表述。
- 总体判断是否与各维度结论一致。
- 报告是否保持自然、准确的中文科技表达。
