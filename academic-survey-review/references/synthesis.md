# 演进、分类与洞察

综述的价值不在于压缩更多论文，而在于建立有依据的关系：问题怎样变化，方法为何分化，证据在哪里一致或冲突，读者据此能作出什么判断。

## 演进脉络

年代顺序只是索引，不自动构成演进。对文章划分的每个阶段检查：

- 当时要解决的核心问题和约束是什么。
- 存在哪些并行、竞争或失败路线。
- 新工作相对于前一阶段改变了什么。
- 变化由新证据、数据、计算条件、理论突破还是评价标准推动。
- 它解决了什么，同时引入了什么代价或新限制。
- 阶段边界和因果关系由哪些来源支持。

演进关系可以包括继承、扩展、替代、复兴、分化、汇合和评价口径变化。不要把后发表自动写成改进，也不要把后来流行的路线写成历史上唯一合理路径。

### 演进判定

| 情况 | 判断 |
|---|---|
| 只按年份列代表工作 | 年代概览，不是充分的演进分析 |
| 说明前后方法的变化但没有动因证据 | 有比较，历史解释仍需核验 |
| 同时呈现竞争路线、转折条件和代价 | 具备演进分析基础 |
| 根据当前技术逻辑猜测当年动机 | 历史归因不成立 |
| 忽略失败路线后声称发展“必然”如此 | 存在目的论或幸存者偏差 |

## 分类框架

先判断分类服务于什么问题，再判断分类本身。依次检查：

1. **分类对象**：分的是论文、方法、模型、任务、系统、证据还是应用。
2. **分类目的**：帮助检索、解释机制、比较取舍、展示演进还是指导选择。
3. **分类依据**：同一父节点下是否采用统一标准；不同层级或父节点可以按对象、条件、环节或方法继续细分。
4. **层级关系**：上位类别、下位类别、属性维度和实例是否归位。
5. **覆盖要求**：按声明范围和组织目的核对关键对象或子问题，不以“可归类”代替内容已经展开。
6. **互斥要求**：类别是否被声明为互斥；若非互斥，交叉关系是否解释。
7. **边界案例**：混合方法、跨类别工作和随配置变化的对象如何处理。
8. **解释价值**：分类是否支持后续比较和结论，而非只让目录整齐。

不要默认所有好分类都必须互斥。多维分析允许同一对象拥有多个属性；应明确“对象 × 维度”，并避免把维度取值、实例和应用混在一组。根据实际组织关系核对完整性：

| 组织关系 | 完整性与边界检查 |
|---|---|
| 并列问题或决策维度 | 是否覆盖回答上位问题所需的关键方面；不要求各项在对象上互斥 |
| 条件分支 | 是否说明划分条件，并覆盖声明范围内会改变结论的重要情形；仅在声明划分互斥时要求无重叠 |
| 方法类别或路线 | 是否覆盖主要路线和必要代表方法，能解释交叉或混合方法；不要求穷举全部实现 |
| 流程或论证阶段 | 是否包含从输入或前提出发到结果或结论的必要环节，并说明依赖；不以路线数量判断完整性 |

发现分类问题时先指出错误对象或标准，再提出调整原则。没有掌握全文范围和领域证据时，不直接给出一套看似完整的固定目录，也不把根据常识推测的主题写成确定遗漏。可以列出待核查维度或条件式组织示例，但必须说明它不是推荐目录。

## 从摘要走向综合

逐篇摘要回答“每篇做了什么”；综合还应回答：

- 多项工作在问题设定、假设、机制和证据上有哪些共同点。
- 表面相似的方法在哪个关键条件上不同。
- 结论冲突来自理论立场、数据、指标、规模、实现还是实验设计。
- 哪些结论能跨场景成立，哪些只在特定条件下成立。
- 方法选择存在什么收益、代价和不可同时满足的目标。
- 哪些空白是真正缺少研究，哪些只是缺少统一证据或评价。

正文应围绕比较问题组织来源。若移除作者和年份后只剩一串互不连接的工作简介，通常仍停留在文献罗列。

## 深度理解

先按作者声明的目的、读者和篇幅确定所需深度，再检查是否从“名称和结果”深入到必要的“机制和边界”。概览型综述需要建立可靠的领域地图与比较口径；机制或教程式综述需要足够展开关键操作与条件；理论综述须交代支撑其理论比较的假设和关键论证。不能把教材式的完整训练流程、实现细节或逐步推导要求强加给所有综述，也不能用篇幅限制掩盖会改变核心判断的缺失。

以下层次用于诊断文章目标所需的展开，不是每篇文章必须逐项完成的模板：

| 层次 | 应回答的问题 |
|---|---|
| 描述 | 有哪些对象，各自做了什么 |
| 比较 | 它们在统一标准下有什么异同 |
| 解释 | 差异为何出现，关键机制是什么 |
| 条件 | 结论在哪些假设、数据和资源条件下成立 |
| 权衡 | 获得某种收益付出了什么代价 |
| 综合 | 多条证据共同支持什么，在哪些地方冲突 |
| 判断 | 读者如何根据目标和条件选择或预测结果 |

篇幅长、公式多或引用多不等于理解深。深度取决于目标所需的关键关系是否被准确解释并有相称证据。仅有提纲时，只能检查是否安排了这些展开，不能确认正文已达到相应深度或断言其缺少细节。

## 洞察

有效洞察应满足：

- 由文章分析或可核验资料推出，而非新造事实。
- 超过单篇文献摘要，但不超过证据支持范围。
- 明确适用对象、条件和可能反例。
- 能改变读者的分类、比较、解释、选择或研究判断。
- 与已有综述相比具有可说明的增量。

将洞察分为：

| 类型 | 处理方式 |
|---|---|
| 作者已明确论证 | 核查推导和证据，评价其贡献 |
| 文章材料可支持但作者未说清 | 作为可加强的综合建议，不冒充作者原结论 |
| 评审者由外部资料提出 | 明确标记为评审建议并给出来源 |
| 证据尚不足的可能方向 | 标记为待验证猜想，不能写成研究空白或事实 |

“很少有人研究”和“首次统一”需要明确检索范围。未找到文献只能说明在已执行检索中未发现，不能证明不存在。

## 综合评价

第三遍结束时回答：

- 文章的领域地图是否与独立核查大体一致，关键差异是什么。
- 演进叙述是否解释问题、变化、竞争路线和代价。
- 分类是否在对象、依据、层级、覆盖和交叉关系上成立。
- 文章是否形成共识、分歧、条件、权衡和研究空白。
- 最重要的洞察是什么，其证据和边界是什么。
- 哪些问题会改变总体结论，哪些只是呈现改进。

无法用文章位置或外部来源支持的判断，不进入确定性评审结论。
