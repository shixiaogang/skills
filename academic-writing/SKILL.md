# 中文科技写作

## 适用范围

本技能只针对中文科技写作。正文、提纲、评审意见与改写示例均使用中文；可阅读外文资料，保留必要的外文术语、缩写、文献题名、代码与数学符号。英文论文或英文摘要的写作、润色不在本技能范围内。

写作前读取当前项目中适用的内容与写作规范，并沿用用户已确定的术语和文风。目录、宏命令、字体、引文位置、图表宽度和编译方式属于项目约定，不提升为所有中文科技文本的通用规则。用户当前要求优先于本技能的默认偏好。

## 核心原则

- **技术准确，证据有边界。** 区分定义、假设、证明、直觉、经验观察与作者推断。不得为了流畅或说服力改变事实、因果强度、量词、条件和不确定性，不编造来源、历史、数据或结果。
- **从读者已知的内容出发。** 先说明当前问题、已有方法的具体不足或推导需要，再引入新概念。核心术语首次出现时紧接白话解释，随后给出所需定义、机制和推导；前文已有动机时直接承接，不重复铺垫。
- **先组织章节，再推进段落。** 讲解性章节优先围绕一个核心问题，从有区分度的视角、维度或方面并列组织主体；各节分别回答子问题，共同形成对核心问题的回答。同层内容保持相近粒度，节内按概念依赖展开，章末综合各方面的联系与取舍。证明、操作流程等有真实先后约束的内容保留递进结构，不为并列而拆断推理。
- **用关系推进论述。** 每段推进一个中心意思，靠并列补充、因果、条件、递进、对比或转折衔接。不能用“首先、其次、再次、最后”替代逻辑，也不能用孤立短句或名词清单让读者猜上下文。
- **保持自然、具体的中文。** 说明什么对象在什么条件下发生什么变化。保留必要主干与承接，避免翻译腔、长串修饰语、空泛赞誉、作者自评和刻意亲切。句长随意思调整，不以短句数量或逐句重复主语衡量清晰度。
- **围绕本节目的选择细节。** 解释分类维度时突出判断标准与可比案例；完整讲解模型时再展开训练和使用过程。定义中的正式陈述、正文中的动机与例子各司其职。表格与图形用于支持解释，不能替代关键推理。
- **首尾呼应，交稿前复读。** 开篇的问题在正文得到回答，结尾收拢答案与适用边界。分别检查逻辑、技术与语言，修订后放回上下文重读；编译通过不能替代文字检查。

## 按任务读取参考

只读取当前任务需要的文件。局部润色不必执行完整研究规划，也不因检查表存在就扩大任务范围。

| 任务 | 读取文件 | 工作重点 |
|---|---|---|
| 规划或重构章节、提纲 | [准备](references/preparation.md)、[结构](references/structure.md)、[中文改写示例](references/chinese-examples.md) 中的章节示例 | 先确定核心问题与拆分依据，再安排并列子问题、层级、共同基础、阅读顺序和综合回答 |
| 起草正文 | [准备](references/preparation.md)、[内容](references/content.md)、[结构](references/structure.md)、[中文表达](references/grammar-and-style.md) | 章内各方面共同回答问题，节内定义、推理、例子与结论形成连贯解释 |
| 修订现有文本 | [成稿检查](references/review.md)、[中文表达](references/grammar-and-style.md) | 先诊断理解障碍；有内容或结构问题时再读取对应文件 |
| 评审或验收 | [成稿检查](references/review.md) | 按实际阅读效果定位问题，再按根因读取其他文件 |
| 概念突兀、短句生硬、比较失配、定义混杂 | [中文改写示例](references/chinese-examples.md) | 对照真实反馈归纳的症状，修复产生问题的原因 |

模型、算法、公式、实验和图表的完整性由“内容”检查；章节分解、同层关系、知识依赖与综合回答由“结构”检查。用户反馈章节松散、只有线性串讲或层级混杂时，直接读取“结构”，先检查各节与全章问题的关系。不要把示例目录或句式变成新的固定模板。

## 执行与交付

1. **确定范围。** 明确体裁、读者、已有材料、用户要修改的对象和成果形式。教学文本以读者学会什么为目标，研究论文以问题、证据和贡献为主，不互相套用模板。
2. **建立有据内容与章节骨架。** 区分已提供事实、可推导关系与缺失信息。整章任务先明确核心问题、拆分依据、各节职责、共同基础和综合回答，再展开正文；缺证据的答案保留为待检验问题。写作简报、章节与段落功能记录、检查表用于内部工作，用户没有要求时不把这些字段写进正文。
3. **按根因修订。** 先查内容与证据，再从章到节到段落修正结构，随后处理清晰度、衔接和语言。章节重构须实际调整材料归属、层级与综合论述，仅改标题或增加过渡句不能算完成。局部润色暴露推理缺口时，回到相应内容补足、收窄或标记。
4. **复核与复读。** 对照 [中文表达](references/grammar-and-style.md) 的语义核验项和 [成稿检查](references/review.md) 的交稿自查，修复适用问题。读者在当前位置需要的信息必须已经出现，不能依赖作者在聊天中补充的说明。
5. **交付所请求的成果。** 直接提供正文、修订稿、提纲或评审结果；文件任务直接修改指定文件。按需简述重要改动、未解决项和核验限制。完整检查过程与逐项合规声明留在内部，除非用户要求展示。

## 处理缺失信息

可通过已有材料或授权检索核实的内容先核实；缺少信息时使用以下中文标记：

| 标记 | 使用场景 |
|---|---|
| `[待核实来源]` | 外部事实、历史归因、文献观点或外部结果缺少可核验来源 |
| `[待补证据]` | 本研究或既有文稿的方法、配置、数据、分析、实验与结果缺失 |
| `[待作者确认]` | 写作意图、取舍、目标范围或尚未实施的研究设计确实存在多种合理选择 |

描述已完成的研究时，缺失方法或配置属于证据缺口，不是等待作者随意决定的设计。标记应说明具体缺什么；未核实陈述若保留在草稿中，标记紧邻该句，不能只藏在文末清单。正式交稿不能把带标记的断言当作已经成立的结论。

不依赖缺口的部分继续完成。只有缺失信息使核心内容无法确定，且不能通过有据的收窄或标记完成当前任务时，才请求补充输入。局部修订不要求用户补齐整篇研究材料。

真实性与技术正确性优先于修辞效果。用户或期刊、出版社的具体要求决定体裁和格式；本技能不处理选刊、投稿系统、投稿信及出版流程事务。
