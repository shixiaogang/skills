# 中文科技写作

## 适用范围

本技能只针对中文科技写作。正文、提纲、评审意见与改写示例均使用中文；可阅读外文资料，保留必要的外文术语、缩写、文献题名、代码与数学符号。英文论文或英文摘要的写作、润色不在本技能范围内。

写作前读取当前项目中适用的内容与写作规范，并沿用用户已确定的术语和文风。目录、宏命令、字体、引文位置、图表宽度和编译方式属于项目约定，不提升为所有中文科技文本的通用规则。用户当前要求优先于本技能的默认偏好。

## 核心原则

- **技术准确，证据有边界。** 区分定义、假设、证明、直觉、经验观察与作者推断。不得为了流畅或说服力改变事实、因果强度、量词、条件和不确定性，不编造来源、历史、数据或结果。
- **问题先行，定义随之而来。** 讲解新方法或新概念必须遵守下文的第一性原理与演进式叙事约束：从具体场景或思想实验出发，展示已有做法的局限，再引出新思路、定义与机制。禁止以干燥的抽象定义起笔；前文已建立具体问题时承接该问题，不重复铺垫。
- **先组织章节，再推进段落。** 围绕核心问题确定主体各自的职责和关系；同一父节点的主体分支采用一致的划分依据，进入下一层可按子问题换用依据。共同基础、具体方法与综合回答各有归属，阅读顺序再按概念依赖安排。证明、操作流程等有真实先后约束的内容保留递进结构，不为并列而拆断推理。
- **用关系推进论述。** 每段推进一个中心意思，靠并列补充、因果、条件、递进、对比或转折衔接。不能用“首先、其次、再次、最后”替代逻辑，也不能用孤立短句或名词清单让读者猜上下文。
- **保持自然、具体的中文。** 说明什么对象在什么条件下发生什么变化。保留必要主干与承接，避免翻译腔、长串修饰语、空泛赞誉、作者自评和刻意亲切。句长随意思调整，不以短句数量或逐句重复主语衡量清晰度。
- **每个细节都回应主线。** 每介绍一个部件、公式、假设或步骤，正文必须明确说明它解决主线中的哪个子问题、为什么需要它，以及怎样推进求解或理解。无法建立联系的细节删去、后移或放入延伸说明。解释分类维度时突出判断标准与可比案例；完整讲解模型时再展开训练和使用过程。表格与图形不能替代关键推理。
- **首尾呼应，交稿前复读。** 开篇的问题在正文得到回答，结尾收拢答案与适用边界。分别检查逻辑、技术与语言，修订后放回上下文重读；编译通过不能替代文字检查。

## 第一性原理与演进式叙事（强制）

这里的第一性原理是从任务目标、已知事实、基本约束与可检查的推理出发，重建“为什么需要这个方法、为什么这样设计”，不能用术语、权威或效果口号代替解释。讲解新方法或新概念时必须完成以下逻辑链：

1. **痛点与困境。** 先构建具体应用场景或思想实验，交代目标、条件与已有做法；展示它在哪种情形下无法满足什么要求，以及局限为何产生。“旧方法不好”或“存在挑战”不算建立问题。数学概念可从一个简单对象、反例或待完成的推导出发。
2. **核心突破。** 从已暴露的缺口自然提出新诉求，再说明新方法改变了哪个假设、表示或操作，以及这个改变为什么能回应痛点。读者理解诉求和直觉之后，再命名概念并给出精确定义；禁止直接抛出定义，再倒补动机。
3. **原理拆解。** 围绕同一主线逐步展开。每介绍一个子部件或子步骤，都必须明确回答：**“这个细节是在解决主线问题中的哪一步骤或哪个子问题？”** 说明当前缺口、该细节的作用和它产生的结果；若是证明前提或适用条件，说明它支撑哪一步推理。不能只列模块、公式和操作。
4. **边界与局限。** 回到起始场景，说明哪些问题已解决、哪些仍未解决、在哪些条件下可能失效，以及引入了什么计算、数据、优化或建模代价。没有证据支持的代价或效果不得编造，也不能以“仍需研究”代替具体边界。

这是强制的解释顺序，不是强制的四个小标题；正文用通俗、严谨、连贯的中文承载逻辑，不能靠“问题／思路／原理／局限”标签掩盖跳步。前文已完成的环节可准确承接或回指；局部修订只补当前理解所需的环节，不擅自重写全文。正式定义仍须准确保留，并置于动机之后。

演进式叙事描述读者如何从已有认识走向新认识，不自动声称这就是技术的真实发明史。保留旧方法在适用条件下的价值；不得为制造突破贬低基线、虚构历史动机，或把教学直觉写成已证明的唯一机制与普遍保证。共用基础、分类比较与既定论文格式仍按各自职责组织，新概念的局部引入遵守上述约束。

## 按任务读取参考

只读取当前任务需要的文件。局部润色不必执行完整研究规划，也不因检查表存在就扩大任务范围。

| 任务 | 读取文件 | 工作重点 |
|---|---|---|
| 规划或重构章节、提纲 | [准备](references/preparation.md)、[结构](references/structure.md)、[中文改写示例](references/chinese-examples.md) 中的提纲示例 | 确定问题与内容边界、同层划分依据、主讲位置及复用，再检查合并后的内部结构与覆盖 |
| 细化提纲中的模型、算法与实现路线 | [结构](references/structure.md)、[内容](references/content.md) | 保留上位任务与问题，在需要完整讲解的位置展开方法；分别检查代表方法、计算与结果恢复是否明确 |
| 起草正文 | [准备](references/preparation.md)、[内容](references/content.md)、[结构](references/structure.md)、[中文表达](references/grammar-and-style.md) | 章内各方面共同回答问题，节内定义、推理、例子与结论形成连贯解释 |
| 修订现有文本 | [成稿检查](references/review.md)、[中文表达](references/grammar-and-style.md) | 先诊断理解障碍；有内容或结构问题时再读取对应文件 |
| 评审或验收 | [成稿检查](references/review.md) | 按实际阅读效果定位问题，再按根因读取其他文件 |
| 保留审查记录、逐章逐句审读或复查多轮修订 | [成稿检查](references/review.md)、[审查记录与记录复核](references/review-records.md)、[规则核对与执行记录](references/review-criteria.md) | 固定版本与覆盖范围，逐项记录适用性、实际动作和证据；分别验收记录质量和正文质量 |
| 概念突兀、短句生硬、比较失配、定义混杂 | [中文改写示例](references/chinese-examples.md) | 对照真实反馈归纳的症状，修复产生问题的原因 |

模型、算法、公式、实验和图表的完整性由“内容”检查；章节分解、同层关系、知识依赖与综合回答由“结构”检查。用户反馈任务太多、章内关系不明或方法只被点名时，先判断是分组、层级还是展开不足，再修改相应范围。用户已确定的结构应承接；仍有影响理解的矛盾时说明依据，不因增加方法就另起一套章节。不要把示例目录或句式变成新的固定模板。

## 执行与交付

1. **确定范围。** 明确体裁、读者、已有材料、用户要修改的对象和成果形式。教学文本以读者学会什么为目标，研究论文以问题、证据和贡献为主，不互相套用模板。
2. **建立有据内容与章节骨架。** 区分已提供事实、可推导关系与缺失信息。整章任务先明确核心问题、拆分依据、各节职责、共同基础和综合回答；长篇任务再分开确定内容归属、详细讲解位置与复用差异。提纲分别检查问题覆盖、可写性与计划深度，再按“具体场景与旧做法局限 → 新诉求与核心直觉 → 定义及逐项回应子问题的机制 → 边界与代价”展开正文；缺证据的答案保留为待检验问题。工作记录与检查表留在内部，用户没有要求时不把这些字段写进正文。
3. **按根因修订。** 先查内容与证据，再从章到节到段落修正结构，随后处理清晰度、衔接和语言。章节重构须实际调整材料归属、层级与综合论述，仅改标题或增加过渡句不能算完成。局部润色暴露推理缺口时，回到相应内容补足、收窄或标记。
4. **复核与复读。** 对照 [中文表达](references/grammar-and-style.md) 的语义核验项和 [成稿检查](references/review.md) 的交稿自查，修复适用问题。读者在当前位置需要的信息必须已经出现，不能依赖作者在聊天中补充的说明。
   用户要求留存记录、逐章逐句审读，或需要追踪多轮长篇修订时，按 [审查记录与记录复核](references/review-records.md) 保存证据。每个声明已检查的单元都须有可回查的依据；“发现问题”“已修改”“复读通过”分别记录。先审记录是否完整、真实，再审正文是否达到交付要求，不能以填满表格或记录通过代替正文通过。
5. **交付所请求的成果。** 直接提供正文、修订稿、提纲或评审结果；文件任务直接修改指定文件。按需简述重要改动、未解决项和核验限制。完整检查过程与逐项合规声明留在内部，除非用户要求展示。

## 处理缺失信息

可通过已有材料或授权检索核实的内容先核实；缺少信息时使用以下中文标记：

| 标记 | 使用场景 |
|---|---|
| `[待核实来源]` | 外部事实、历史归因、文献观点或外部结果缺少可核验来源 |
| `[待补证据]` | 本研究或既有文稿的方法、配置、数据、分析、实验与结果缺失 |
| `[待作者确认]` | 写作意图、取舍、目标范围或尚未实施的研究设计确实存在多种合理选择 |

描述已完成的研究时，缺失方法或配置属于证据缺口，不是等待作者随意决定的设计。标记应说明具体缺什么；未核实陈述若保留在草稿中，标记紧邻该句，不能只藏在文末清单。正式交稿不能把带标记的断言当作已经成立的结论。

不依赖缺口的部分继续完成。只有缺失信息使核心内容无法确定，且不能通过有据的收窄或标记完成当前任务时，才请求补充输入。局部修订不要求用户补齐整篇研究材料。

真实性与技术正确性优先于修辞效果。用户或期刊、出版社的具体要求决定体裁和格式；本技能不处理选刊、投稿系统、投稿信及出版流程事务。
