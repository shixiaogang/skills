# 中文表达与行文

用于起草、修订和检查中文正文。先确认要表达的关系，再调整句法；读起来顺畅不能补偿技术含义的变化。内容缺失转到 [内容](content.md)，段落职责或顺序失配转到 [结构](structure.md)。

## 保持技术含义

编辑前记录当前片段适用的语义核验项，编辑后逐项对照：

- 论断及其强度，量词、否定、充分性与必要性；
- 对象、范围、群体、条件与例外；
- 不确定性和限制性措辞；
- 数字、单位、分母、聚合方式与比较基准；
- 公式、逻辑关系、因果与相关的区别；
- 引文、归因、术语与已定义符号。

若原文有多种合理解读，先利用上下文和来源消除歧义；无法确定时按入口文件标记，不擅自选择更强的解释。发现可核实的技术错误，应纠正并说明实质变化；无法核实的疑点保留为待核实项，不能无声改动。

## 句子完整，但不机械模仿英文句法

中文正文应语意完整、主干清楚，读者能确定对象、动作及其关系。避免把“先固定任务”“再看容量”“还有几个条件”等提纲片段直接当正文；应解释为什么需要这一步，以及它承接什么问题。

同一话题连续展开、动作承担者明确时，可以自然承前省略主语。不要机械要求每句重写“我们”“该模型”，也不能省到让读者猜谁在执行、什么在改变。标题、表头和算法步骤按各自功能书写，不套正文句式。

| 阅读障碍 | 修改方向 |
|---|---|
| 只有动作标签，如“再看容量” | 写清要考察哪个对象的什么性质，以及为何接在此处 |
| 连续短句各自正确，却缺少联系 | 补出因果、条件、比较对象或承接句，必要时合并 |
| 同一主语反复出现，行文僵硬 | 在指代唯一、层次清楚时合并分句或自然承前 |
| 一个长句包含多层转折与独立结论 | 拆分论证动作，把限定放在所约束的判断附近 |

## 具体说明对象、动作和条件

优先使用准确动词：“算法更新参数”比“参数更新操作得到了执行”清楚。名词化可以命名稳定概念，但不能遮住过程。不要把“具有能力提升作用”当作“在什么条件下改善什么指标”的替代品。

通常用主动表达说明谁做什么；需要突出承受对象时可以用被动句。选择取决于信息焦点，不以消除所有“被”字句为目标。定义和分类中的“是”、状态描述中的“具有”并不天然软弱，不为追求有力措辞而加强因果。

拆开过长的“的”字链和层层套叠的定语。先让读者知道讨论什么，再展开解释；决定结论是否成立的条件应在结论之前或附近出现，不能一律移到句末。尤其检查“仅”“主要”“近似”“平均”“至少”等词究竟限定哪个对象。

## 衔接依靠真实关系

句子通常从前文已有信息接起，再引入新信息。段落之间应能解释：前一结论带来什么新问题，哪个条件改变了，已有解释还缺哪一步，或正在转向同一问题的另一个方面。并列展开时说清共同问题和视角变化，不必给前文制造不足，也不能写成虚假的因果。必要时补完整的承接句，不能只加“此外”“因此”掩盖内容跳跃。

- “它”“这”“其”“该方法”可能指向多个对象时，重复准确名称。
- “因此”“所以”要求前文足以支持后文；相关、先后或个例不能直接推出因果和普遍结论。
- “但”“然而”应指出与前文哪项判断形成转折。读者尚未形成相反预期时，不突然用“其实”“并不”“也不一定”纠正一个未提出的误解。
- “还需要”“再考虑”应接上已完成的步骤或已指出的不足，不能凭空起句。
- 正文不用“首先、其次、再次、最后”机械串联段落；真正有先后要求的操作或算法可以编号。

例如，“还要明确使用哪一组输入特征”缺少当前判断对象。若前文讨论线性结构，可写“判断模型是否具有线性结构，还需要明确所使用的输入特征”。补入的是必要关系，不是装饰性过渡。

## 术语要有解释，名称要稳定

核心术语首次出现时，读者应已知道它要解决什么问题；紧接一句白话说明它表示什么、在当前问题中起什么作用，再给出所需的精确定义。中文译名、外文全称和缩写都不能代替解释，更不能用另一个未解释的术语来解释它。

- 先查项目既有译名和符号。一个概念保持一个名称，不为了避免重复而轮换同义称呼。例如既定名称为“模型族”时，不随意换成“模型家族”。
- 对需要与文献对应的核心术语，首次写作“中文名称（常用外文名称，缩写）”；缩写仅在后文反复使用且确有帮助时引入。项目若要求所有术语标记配外文名称，应检查是否遗漏，不必给普通中文词语逐一加外文。
- 比较相近概念时，说明区别落在哪个对象、条件或用途上，不只连排两段定义。
- 用“考察什么”“如何判断”代替抽象标签堆叠。“整个模型族”“接口选择”等说法若承载关键含义，应就地解释所指对象与判断标准。
- 中文正文使用中文标点；外文术语、代码和公式内部保留其格式。引文位置、专名写法、空格与术语宏遵循项目或出版要求，不自行推广某个项目的排版约定。

## 自然语气与阅读节奏

专业程度体现在解释和论证中。保持严谨、平实、有耐心的语气，少用长串修饰和抽象套话。删除不增加信息的“不可否认”“令人振奋”“众所周知”“值得一提的是”“旨在赋能”“具有重要意义”等表达；若价值确实重要，写出它体现在哪里。

长短句随内容交替。一句只推进一个主要意思，但紧密相连的判断不必拆成生硬碎片。精简应先删除离题和重复内容，再删句内冗余；不能删掉承接、解释、比较基准和必要条件。

在教材、技术笔记和讲解文章中，可以用“我们”带领读者观察、假设和推导，用“你”提示尝试或检查。研究论文按体裁选择“本文”“本研究”或中性表达。不要逐句添加代词，也不用“相信大家已经明白”“你一定会觉得”替读者下判断。

解释复杂逻辑后，补上读者最可能卡住的一步：为什么可以这样变形，这与刚才的概念有何区别，条件不满足会怎样。可以偶尔设问，不把每段写成自问自答。避免用“显然”“不难发现”跨过关键推理；已有足够依据的常规步骤可简写，不必事无巨细。

## 避免讲义标签与作者自评

正文用连贯段落展开机制与推理。不要反复套用“背景。……模型形式。……参数估计。……”或加粗小标签；去掉粗体却保留同样的碎片结构，也没有解决问题。

真正并列的事项、操作步骤或多维比较可用列表和表格。冒号、分号用于清楚呈现已经成立的关系，不把长串“甲是……；乙是……；丙是……”塞进一句话以代替解释。

直接陈述对象、条件和关系。删去“这个形式看起来朴素得不像模型”“理解模型不宜只记名称”等作者评价或读者训导。必要的范围说明、学习路线和跨节引用可以保留，但要说明各部分为什么相连，少写“本节不追求……而是……”一类写作意图声明。

预告放在读者能理解其意义的位置。同一小节不要反复说“后文将用……”“下面各节将……”。若先用例子建立了整体认识，后续路线可以在例子之后集中交代，不打断正在展开的解释。

## 让措辞与证据强度一致

| 内容性质 | 合适的中文表达 | 不应自动升级为 |
|---|---|---|
| 观察 | “在该样本中观察到……” | “普遍证明……” |
| 限定比较 | “在这些设置下，相对于基线……” | “在所有情况下优于……” |
| 初步推断 | “初步结果提示……可能……” | “证实……必然……” |
| 相关关系 | “与……相关” | “导致……” |
| 形式化结论 | “在假设……下，可以推出……” | 无条件保证 |
| 未检测到效应 | “未检测到……，估计仍有不确定性” | “不存在……” |

“显著”若表示统计显著性，应有相应检验依据；若只表示差异幅度，尽量直接报告差异。不删除“可能”“平均”“在测试范围内”等实质限定，也不靠层层“似乎可能大概”掩盖不知道。

以下为虚构的中文编辑示例，数值不是实验结论：

> 原句：我们所进行的初步实验，在规模为128并使用工作负载甲的情况下，初步地提示了采用式（3）的求解器相对于基线乙可能使平均延迟降低17.4%。
>
> 改写：在规模为128、使用工作负载甲的条件下，初步实验提示，采用式（3）的求解器相对于基线乙可能使平均延迟降低17.4%。

改写删除重复措辞，保留实验的初步性质、规模、负载、公式、比较对象、指标、数值与不确定性。涉及此类问题时，继续参看 [中文改写示例](chinese-examples.md)。

## 修订后复读

把句子放回原段，连同前段结尾和后段开头一起读。检查对象是否清楚、转折是否有来由、新术语是否有铺垫、条件是否贴近结论。再对照本文件开头的语义核验项；局部顺畅但主线偏移时返回结构修订，不继续只磨句子。
