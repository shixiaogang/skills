# 审查记录与记录复核

用于用户要求保留审查记录、逐章逐句审读，或需要追踪多轮长篇修订的任务。目标是让另一位审查者能够核实：检查了哪个版本、实际读到了哪里、判断有什么依据，以及问题是否确实解决。短小修改可用紧凑记录；不把完整流程强加给普通单句润色。

记录放在项目允许保存的文件位置，与正文分开。沿用项目既有目录和格式；没有约定时可用 Markdown。用户指定的留存要求优先于默认不展示内部检查表的偏好。不能把记录字段和审核声明塞进教学正文，也不把一次性过程材料混进现行内容大纲。

## 固定可回查的对象

每份记录注明：

- 记录编号、日期、记录自身修订号及可恢复位置、审查者及角色。AI 自查、另一代理的复核与真实读者反馈分别注明，不能冒称真实读者实验或人类独立评审。
- 源文件或文档标识、版本及实际阅读范围。Git 项目记录提交值；检查未提交内容时记录文件摘要及可恢复的全文版本，不把 HEAD 当作未提交正文的版本。正文和记录都须能恢复受审版本：已有 Git 对象时不重复保存快照，尚未保存到版本历史时保留必要的受审输入。摘要只能识别内容，不能恢复被覆盖的文件。
- 章节或小节标签、段落编号、可核实的短引文；行号辅助定位，不能成为唯一定位依据。公式、例子和图注保留各自标识。
- 目标读者及所依赖的前置内容；未读到的前文、未核查的来源、图源和版面明确列为范围限制。

先核对版本，再读结论。正文变化后，旧记录保留历史价值，但受影响部分须标为待重审；不能继续拿旧版本的“通过”为新正文背书。

## 留下阅读和推理依据

对每个小节记录当前要回答的问题及预期读后所得。写作意图或拟重排主线与从现有正文实际读出的主线分别注明，不能把计划中的好结构冒充当前文字已做到。

每个段落至少交代：它实际推进哪个子问题、前文已提供什么、它与前段是什么具体关系，以及读者进入下一段还缺什么。关系必须写出对象和依据，例如“前段只改变同一封邮件的排版，本段转向整批邮件中困难模板的比例，但尚未说明为什么换评价对象”，不能只写“递进”“有过渡”。段落职责和首尾呼应同样可以判为未建立。

用户要求逐句阅读时，为范围内每句话留下定位和判断，至少包含短引文、所属段落与子问题、问题编号或具体接受理由。连续句子确实共用一项判断时可以合并，须显式列出被覆盖的句子编号；只给段落摘要不能证明已经逐句检查。公式、例子与图注单独纳入覆盖；其内部标记和排版代码不必伪装成正文句子。

覆盖清单区分已检查、未检查和不适用。未发现问题的单元也须有简短依据，例如“例子给出了两组比例与错误率，加权结果可复算”，不能整页复制“通顺、无问题”。以有据判断为目标，不为每句话强行找缺陷。

文本单元覆盖和规则执行是两项检查。按 [规则核对与执行记录](review-criteria.md) 建立规则台账：为每项规则注明适用对象、实际检查单元、定位证据、判断理由、发现编号及状态；同一证据可支撑多项规则，但须分别解释为何支撑。不能因为某段已读，就默认所有适用规则已检查。

规则状态使用通过、未通过、未检查、不适用、约定范围外五种。不适用须用对象或体裁证据说明触发条件不成立；约定范围外须引用范围依据，不能伪装成不适用。缺前文、文献、图源或版面通常是未检查；只检查了部分适用单元时仍登记未检查，并保留已完成范围及尚缺单元。总体通过须覆盖该规则在声明范围内的全部适用单元，不能由一个例子外推其余段落。

项目规范和用户新增要求进入本任务的扩展规则表，沿用相同的动作、证据和状态字段。既有规则的来源、条件或内容变化时重审对应映射和受影响记录；新规则不能无声沿用旧版本的通过结论。

## 记录发现、修订与复读

每个发现用稳定问题编号连接以下信息：

| 字段 | 应当提供的证据 |
|---|---|
| 位置与原文 | 可核实的原句、段落或公式，所对应的版本 |
| 理解障碍或技术疑点 | 读者缺少哪个对象、条件、前提或推理环节；疑点如何影响结论 |
| 根因与修改动作 | 移动、补充、合并、删除或收窄什么；不要只写“优化表达” |
| 状态 | 待修改、已修改待复读、复读未通过、复读通过，或有据撤销 |
| 修订证据 | 修改后版本、实际位置及短引文或差异；未修改时明确写“未修改” |
| 复读证据 | 谁在什么版本上读了哪些前后文，如何判断原障碍已消除，是否引入新误解 |

撤销发现时说明原判断为何不成立，指出正文已存在的支持或其他反证。建议、聊天中的示范段落和尚未写回正文的改稿，不算实际修订。

问题关闭分两种路径：实际修订项须有改后原文及对应版本的上下文复读证据；误报撤销项须有反证、原文支持及原版本的上下文核验，不要求为撤销误报制造正文修改。“换了句式”“公式没变”“构建通过”不能证明读者的理解障碍已解决。因缺前文或来源尚未确认的问题保留待核实状态，继续处理不依赖它的部分。

## 复核记录本身

记录复核者阅读实际正文和记录，不只看填写结果。能安排独立审查者时，由未参与被审单元及影响其判断的上下文改写的人或代理承担，并准确注明身份及相关参与经历。复核记录的独立性与复核正文的独立性分别说明；修改过无关章节不自动失去独立资格。否则明确记录为作者自查，不能声称独立复审。

核对四件事：

1. **对象与覆盖真实。** 版本和引文能够对应；声明逐句检查时，覆盖清单无遗漏、重复冒充覆盖或未说明的跳过。图注、公式和例子不因格式不同被漏掉。
2. **判断有正文支持。** 复核具体缺陷及接受理由，检查记录是否借用作者聊天、后文或拟修改内容补足当前正文。逐句检查的任务复查全部声明单元；其他任务可按约定范围抽查，但必须注明实际抽查项，不能由抽查宣称全部通过。
   同时核对规则台账的适用性、动作及证据：规则原文是否完整映射，未检查项是否被遗漏，单句的局部通过是否被扩大为整条规则或整章通过。规则表的格式校验不能代替这个判断。
3. **推理与技术条件成立。** 审查者能够用自己的话复述主线和段间关系；条件、量词、数值和指标方向没有为叙事流畅而改变。复核者无法建立某一步关系时回到正文定位，不用“逻辑完整”代替说明。
4. **关闭有证据。** 每个修订关闭项有新版本原文、上下文复读及结论依据；每个撤销项有反证、原文支持与上下文核验。新增缺陷仍列为未解决。版本变动后重新检查受影响的术语、引用和前后段关系。

复核结果另存一节或一份关联记录，注明被审记录编号及版本、复核者、范围、具体发现和处理结果。发现记录缺陷时，引用记录位置或单元编号，说明哪里与正文不符、哪些覆盖或关闭证据缺失；修正后保留可追踪的复核轮次。审查循环以约定范围完成且无未解决记录缺陷为止，不以评审者数量或轮数衡量可信度。

格式检查、摘要校验和覆盖核对可以自动化。它们验证可定位性与完整性，不能证明段落易懂；技术与阅读判断仍需回到正文。记录审查结束时分别给出：

- **记录结论：** 可接受／需补充／不可信，并说明依据及未核查范围。
- **正文结论：** 待修改／待复读／在声明范围内通过／证据不足。记录可接受时，正文仍可能存在明确缺陷。

## 紧凑记录模板

按任务裁剪字段，但不能省略支撑所声明结论的证据。

```markdown
# 写作审查记录：<主题>

记录编号、日期、自身修订号及可恢复位置、审查者与身份：
源文件、版本、摘要及可恢复位置、标签及范围：
读者前置知识、实际阅读范围、未核查内容：
拟回答的问题：
从当前正文实际读出的主线及缺口：

## 段落与逐句覆盖
| 单元及定位短引 | 对应子问题与段落作用 | 与前文的具体关系／阅读判断 | 发现编号或接受理由 |
|---|---|---|---|

## 问题与修订
### <问题编号>
位置及原文：
读者缺什么／哪项技术条件有疑点：
根因及修改动作：
状态：
实际修订证据（版本、位置、短引）：
上下文复读证据（审查者、版本、覆盖、理由）：

## 记录复核
被审记录版本、复核者身份及实际范围：
具体发现、反证及处理结果：
记录结论与依据：
正文结论与未解决项：
```
