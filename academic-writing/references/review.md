# 成稿阅读与交稿检查

用于评审、修订和验收中文科技文本。目标是判断目标读者能否只凭当前位置以前的正文理解问题、跟上推理，并把握结论及边界。每次评审都必须同时使用 [审查记录](review-records.md)，保存章级、段级、句级覆盖及问题闭环证据。阅读顺畅不能代替来源核实、实验验证、证明审查或最终版面检查。

## 确定模式与边界

记录实际检查的文档、版本、目标读者和前置知识。若章节入口还包含其他片段、附录或生成内容，沿实际组成关系确认受审全文；不能只读短入口就声称审完一章。只有片段时，仍须执行三遍审读并记录该片段在章级主线中的可核查位置；缺少完整章节或必要前文时，章级结论为证据不足，不能省略这一层。

模拟首次阅读时，只使用目标读者合理掌握的背景和当前位置之前已经出现的信息。专业知识、作者在聊天中的补充、后文解释和交叉引用可以帮助确认作者意图，却不能倒算当前位置已经解释充分。后文补释若来得太晚，仍须判断前文是否要求读者猜测，以及补释是否与已有内容重复。

所有评审均执行下述三遍流程，没有只做段落或句子层检查的简化模式。用户只要求评审时交付问题与必要的局部示例；用户要求修改时，完成修订并复读。材料不足不改变流程，只降低相应结论。

## 严格执行三遍审读

三遍分开执行。每遍回答不同层级的问题，不能倒序，也不能用句子层面的润色代替章节结构判断。

### 第一遍：章节逻辑

连续通读全文，不在途中陷入措辞修改。读完后凭实际理解重建：

- **C1 核心问题。** 开头建立了什么具体问题，目标读者是否具备进入正文所需的前置知识。
- **C2 章节分解。** 各节分别回答什么子问题，同层划分依据、职责和阅读顺序是否成立。
- **C3 承诺兑现。** 开头承诺的对象、过程、条件和学习所得是否在主体中实际展开；一个分支写得充分不能替其他分支通过。
- **C4 综合收束。** 结尾是否回答开头的问题，并说明结论、成立条件、代价和仍未解决之处，而非只换一种说法复述目录。

整章审查建立“章首承诺—主体位置—实际展开—结论”的对应关系。拟写意图与当前正文实际做到的事情分开记录，不能把大纲中的好结构当作正文已经实现。

### 第二遍：段落逻辑

按自然段重读，逐段说明：

- **P1 中心作用。** 本段解决哪个子问题，是否只推进一个可说明的中心意思。
- **P2 前后关系。** 本段承接前文的哪个对象、结论或缺口，为什么此处转向，又为下段留下什么。
- **P3 理解顺序。** 是否先给当前场景、任务、现象、反例或待证明命题，再暴露缺口，最后引入术语、抽象判断、定义、记号或方法。
- **P4 细节职责。** 公式、定义、例子、图表、假设和新记号为何在此出现，它们推进了哪一步。
- **P5 层级与范围。** 是否存在重复、层级混列、场景突换或范围突然扩大；对象、总体、评价单位、条件或量词改变时，是否写明转换依据。

每个新节、主要小节和方法入口都单独检查局部立足点。章首远处的例子只有被明确回接时才能继续作为前提。复用同一例子或重新讲解已定义概念时，比较此前所有相关段落，确认新段落确实补充了新的区分、机制、条件或边界；迟到的必要解释应前移、合并或删除。

### 第三遍：句子与用词

逐句复述实际意思，再检查：

- **W1 句子主干。** 谁或什么，在什么条件下，对什么做了什么；指代和省略是否唯一。
- **W2 词义与关系。** 动词、名词组合、修饰语和关系词是否给出可观察对象或可判断关系，而非用抽象标签让读者猜。
- **W3 术语与符号。** 新术语、缩写、技术组合词和符号是否及时给出白话含义、评价对象或用途，后续含义是否一致。
- **W4 逻辑限定。** 否定、转折、因果、比较、量词、程度词和条件词是否有依据且作用范围明确；含多重否定或否定中嵌套例外时，先展开成正向命题核对，正文若仍要求读者自行消解则登记问题。
- **W5 技术与证据边界。** 指标方向、公式含义、事实强度、直觉、假设、观察与结论是否准确区分。
- **W6 逐词必要性。** 语序、句界和标点是否自然；每个词是否提供必要信息或建立明确关系，是否存在空话、重复或粘连句。

连续短句确实共同完成一个动作时可以合并判断，但须列清覆盖范围。公式、定义、例子、图注、表注和算法步骤不能因格式不同而漏查。

## 七项专项门槛

以下门槛决定一个适用单元能否判为接受。每次评审须在声明范围内检查全部适用门槛；缺少完整章节时保留未检查项，不得把它们视为不适用。

1. **可检验命题。** 含要求、标准、保证、约束或能力判断的句子，应能不靠增补改写成“对象在条件下满足某项性质、动作、指标或阈值”。缺少承载对象、条件或判断标准时登记问题。
2. **压缩表达拆解。** 定义、分类或比较中的名词组合、程度词和关系词要能展开。对“表现、效果、接近、更好”等词核对评价对象、指标、方向、数据范围和基准；对“与……有关、相应、这种”等词核对关系两端、关系类型和可观察的判定依据。
3. **新对象转换。** 首次出现新的模型集合、评价单位、总体、条件分布、环境或范围时，说明它从前一对象怎样推出、为何现在需要切换，以及固定什么、改变什么。审查者能够凭专业知识猜到，不等于正文已经搭桥。
4. **解释时序。** 记录新概念的问题或反例、命名、白话解释、正式定义和例子各自出现的位置。后文首次补足理解定义所必需的信息，不能倒算前文通过；重复使用例子或重新讲解同一概念时，正文须明确此前尚缺的问题和本段新增的解释任务，不能只由审查者替它归纳教学价值。
5. **局部入口。** 新节、主要小节和新方法的开头先建立本地可用的具体场景、数学对象、反例或待证明命题，再引出抽象判断。恢复必要背景后立即提出新问题属于正常承接，不要求机械重复完整动机。
6. **公式双门槛。** 核心公式先沿当前场景说明缺少什么可计算对象、为何此时需要它和它将回答哪个问题，再定义符号。使用最小值、上确界、期望、阈值或约束时，还要说明候选或允许集合从哪里来、按什么指标和方向比较，以及为何选择该运算；最坏情形目标还须解释为何要求覆盖集合内每种情况、平均量为何不足。
7. **回指与范围。** 抽象回指要在本地恢复当前推理所需的命题。扩大对象或变化范围时，写清原范围、新范围、扩大理由、旧结论可继承的部分，以及需要改变的定义、条件或评价标准。

讲解一个模型或算法时，按实际适用性检查这条依赖链：具体任务或数学问题 → 旧做法缺口 → 预测或评价对象 → 误差或残差 → 损失动机与总体目标 → 经验目标 → 求解方法及成立条件。不适用的环节说明原因；后文最终提到某一环节，不能证明入口顺序合理。

## 人工反馈校准示例

以下 12 项来自人工审读中已经确认的严重问题，是评审必须能够识别的最低校准集。它们用于说明失败根因，不把原句固化为关键词；遇到换词后的同类问题仍须检出。

| 编号 | 典型原句或症状 | 必须识别的缺口 |
|---|---|---|
| E1 | “训练域的留出表现接近” | 没有说明比较哪些数据、使用什么指标，以及“接近”相对于什么基准；对应压缩表达与比较口径。 |
| E2 | “与使用后果相关的子类型” | 没有说明关系两端、哪些后果会随子类型改变，也没有具体情形解释标签或评价分组遗漏了什么。 |
| E3 | “要求可以落在概率的频率含义……” | 没有说明是什么要求，也没有指出要求约束模型输出、预测集合、决策规则还是系统行为。 |
| E4 | “不一定在增加观测信息后仍不可减少” | 多重否定把正向变化藏起来；应直接核对并表达“增加观测信息后可能减少”一类命题。 |
| E5 | “有限数据可能支持多个不同预测模型，模型之间的分歧可能减小” | 没有解释为何有限数据对应多个候选模型，也没有从前文场景搭桥到模型集合及其分歧。 |
| E6 | “对邮件分类器，可以固定可见特征来理解这一区别”及后续重复对照 | 没有指出前文尚缺什么、本段新增什么解释；具体例子只是迟到铺垫或重复已有区分。 |
| E7 | “沿用基础章的三个问题，先规定模型应当承受哪些变化，以及变化后至少保持怎样的表现” | 没有就地回顾三个问题，也没有说明承载对象、允许的变化范围和评价依据。 |
| E8 | “变化本身不是脆弱性” | 节首先抛出抽象判断，没有先建立会导致问题的具体变化、观察、反例或待证明命题。 |
| E9 | “最不利变化” | 没有解释允许哪些变化、允许集合由什么确定，以及按什么指标和方向判断“最不利”。 |
| E10 | “局部扰动并未涵盖全部分布变化” | 从局部扰动扩大到一般分布变化时，没有说明二者关系、扩大范围的理由及旧结论可以继承到哪里。 |
| E11 | “对于回归或分类器 \(f\)，环境 \(e\) 中的风险记为 \(R_e(f)\)” | 突然转入一般模型和新记号，没有承接当前场景，也没有先说明为何需要这个可计算量。 |
| E12 | “绝对风险和下降幅度需要一起看” | 没有说明变化的是风险、准确率还是其他指标，哪个方向表示恶化、相对什么基线计算，也缺少说明两者为何必须同时考察的具体例子。 |

逐章审查须在记录中逐项标明 E1—E12 是否触发、检查了哪些位置及判断依据。不适用必须以正文对象或触发条件为依据，不能只写“未发现”。这些例子全部未触发，也不能替代 C1—C4、P1—P5、W1—W6及七项专项门槛的全文检查。

## 转向专题核验

三遍审读负责发现理解障碍和定位根因。结构或材料归属问题转到 [章节结构](structure.md)，定义、公式、算法、实验、图表和证据问题转到 [技术内容](content.md)，句法、术语、衔接和语气问题转到 [中文表达](grammar-and-style.md)。按疑点读取，不在本文件重复执行各专题的完整清单。

不能用“符合常识”“整体流畅”、编译成功或检查表已填满代替技术与阅读判断。

## 按根因修订并闭环

优先修复阻断理解、扭曲技术含义或改变证据边界的问题，再处理局部费力。相同根因影响连续多句时合并为一条发现，不为增加数量拆分。

若支持已经在材料中但位置不对，移动、合并或明确回指；若关系本身缺失，核实、收窄或标记，不替作者编造机制。不能靠给每节添加同一模板、删除必要技术内容或把关键条件移入边注来获得通过。

修改后先核对技术含义，再从受影响位置之前连续读到后续衔接；新增问题继续修订。整章最后重新顺读，分别确认原发现已关闭且没有引入新缺陷。“已修改”“编译通过”或达到预设轮数都不等于复读通过。

## 通过与交付

只有在完整章节的实际组成范围全部读完、章级、段级、句级三遍覆盖均有记录、适用门槛全部执行、成立的发现均有修订后复读或有据撤销证据，且没有已知未解决的技术或阅读问题时，才能判为通过。只提供片段或缺少必要上下文时可以给出局部发现，但正文结论保持证据不足。来源、图源、证明、程序执行或版面未核查时，明确列为限制。

评审结果先列高影响发现，再说明位置、短引、读者缺少什么、根因和最小动作。区分必须修正的技术或理解障碍与可选文风偏好。修改任务以实际修订稿为主，说明剩余项和核验限制。

单一审查者可以完成三遍阅读，但只能称自查。只有未参与相关正文和记录修改的人或代理实际复读了声明范围，才称独立复核；不规定固定审查人数，也不以人数或轮数代替覆盖和证据。
